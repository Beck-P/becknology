# Bridge — Art Direction

This file is the single source of truth for the **bridge app's** visual style — applies to `apps/bridge/` only, not to any other Becknology app. All procedural drawing AND all PNG asset generation for the bridge must conform to this spec. If a new asset doesn't fit these rules, the asset is wrong, not the rules.

> **Agents (Claude Code, Codex, etc.):** copy/paste prompts live in `apps/bridge/PNG-PROMPTS.md`. The full master prompt is also embedded in this file under "PNG generation rules" so either is a valid source.

## North star
**Cast n Chill meets Stardew Valley.** A cozy 2D world that feels alive — very slightly pixelated, painterly light, rich small detail: Stardew's readable top-down map and high-oblique building sprites (full facade visible AND most/all of the roof plane visible from above), with Cast n Chill's richer detail, mood lighting and constant small motion (smoke, flicker, water, breathing idles). We are intentionally hybrid — AI-painted PNGs, Blender-rendered sprites and procedural canvas drawing all meet on **one native pixel grid**, under one lighting model. The job of this doc is to keep those paths looking like one game.

## Rendering pipeline (js/world.js)

1. Each frame the world is painted into a small offscreen canvas at **32 native px per tile**, then scaled to the screen by a **whole number** of device pixels (`zoom`). Never draw world art straight to the screen — everything lands on the same pixel grid this way.
2. The camera snaps the world to whole native pixels; the leftover fraction shifts the finished frame, so scrolling stays smooth.
3. Draw order: background → tiles (static ones from a cache) → glow → tileset overlay → loot → **pilot** → tall sprites whose base is below the pilot (so the pilot can walk behind buildings) → lighting → effects → screen-space UI (exit beacons, game markers, vignette — crisp text at CSS resolution).
4. Static tiles are detected automatically at world load (drawn at several sample times; tiles whose pixels change, or that paint outside their cell, stay live) and cached. A few cached rows are refreshed every frame, so state-driven drawers still update. Call `BridgeWorld.invalidateTiles()` after changing what a static tile looks like.
5. Movement, camera and animation run on real elapsed time (`dt`), never frame counts.
6. Inside a background or overlay drawer, use `BridgeWorld.getView()` (`{offX, offY, ts, w, h}` in native px) — not `getScale()`/`getCamera()`, which describe the screen. For mouse picking / DOM placement use `BridgeWorld.getScreenView()` (CSS px).
7. The main canvas's size and scale are set every frame (`js/main.js`): a window moved to another screen changes its pixel density without a resize, and a canvas the browser drops and hands back (short of graphics memory) comes back unscaled — on `contextrestored` the scene composites and sea textures are rebuilt too.

## Resolution & scale

| Concept | Value |
|---|---|
| Native tile | 32 × 32 px (`ts` passed to every drawer) |
| World data tile | `tileSize: 16` in world JSON is a logical unit — don't change it |
| Procedural unit `u` | `ts / 16` = 2 native px (procedural art is still authored on a 16-unit grid) |
| Sprite density | 32 native px per tile — 1 native px of detail |
| Screen zoom | whole number of device px per native px, chosen so ~20 tiles fit across |
| All scaling | nearest-neighbor only — `imageSmoothingEnabled = false` (except the light map, which is soft on purpose) |

## Procedural drawing rules — match the PNG style

The procedural drawers in `js/worlds/*.js` should look like they were drawn at 16 logical pixels per tile, even though they're rendered with `fillRect`. This is what keeps procedural and PNG art looking like the same family.

**Rules:**
1. **No sub-pixel detail.** Every `fillRect` width/height should be a whole multiple of `u` (or at minimum `Math.max(1, u)` for thin lines). Avoid `u * 0.4`, `u * 0.5`, etc. — those are vector-style.
2. **Limited palette per element.** 3-4 tones max: highlight, midtone, shadow, deep shadow. No smooth gradients in foreground objects (gradients are OK for sky/sea/halo backgrounds where we want a soft fade).
3. **Hard edges.** Pixel-perfect color boundaries. No anti-aliasing.
4. **1-pixel outlines on subjects.** Most foreground objects should have a `Math.max(1, u)` dark outline — matches Stardew and PNG style.
5. **Animation as overlay.** Animation goes in a separate pass on top of static art (see `drawChimneySmoke`, `drawWindowFlicker`). Keep it cheap and frame-based — small additive sprites or simple `Math.sin` modulations.

## PNG generation rules

**View angle: high oblique elevated front-facing RPG building view.** The building faces directly forward with the full front facade readable, AND most or nearly all of the roof plane is visible from above. The roof should feel almost top-down while the front wall stays fully visible. This is the classic farming-RPG building sprite that drops onto a top-down tile map (Stardew, Harvest Moon, Rune Factory).

**Not allowed:** true isometric, diagonal rotation, realistic vanishing-point perspective, side view, or pure top-down roof-only view.

**Composition:**
- Door at bottom-center so the building sits naturally on a tile map.
- Roof plane visible from above at a strong high oblique — most/all of the roof readable.
- Front facade fully readable below the roof.
- Windows are clearly defined frames with simple yellow-glow glass — *no detail painted inside the window*. We layer animated glow on top.
- Chimney (if present) at upper-right or upper-left of the roof, with empty space *above* the chimney top. We draw smoke procedurally there.
- Lantern (if present) beside the door, with a small flame shape. We replace the flame with animated procedural flicker.
- Hanging sign (if present) attached to a corner of the upper floor by a chain/bracket.
- Stone or wooden foundation visible at the base, sitting on the ground.

**Master prompt (paste into every PNG generation — long form):**

> Create a pixel art PNG of a [BUILDING TYPE] for a cozy 2D farming RPG.
>

Show most or nearly all of the roof plane from above, with a strong high oblique angle. The roof should feel almost top-down while the front wall remains fully readable. This should look like a classic farming RPG building sprite placed on a top-down map. Keep the entrance near the bottom-center so the building sits naturally on a tile map.
>
> **Perspective rules.** No true isometric perspective. No diagonal rotation. No realistic vanishing-point perspective. No side view. No pure top-down roof-only view. The angle should be a fixed high oblique building sprite view.
>
> **Pixel art style.** Chunkier, more visibly pixelated high-resolution pixel art. Strong visible pixel blocks and pixel clusters. Crisp hard edges. No anti-aliasing. No smooth painting. No blur. No realism. No 3D, no voxel, no low-poly. Clear dark outlines. Slightly simplified forms so the sprite reads cleanly. Cozy retro RPG aesthetic. Warm, inviting lighting. Clean sprite-like shading. Readable at small size.
>
> **Visual language / consistency.** Same camera angle, roof visibility, pixel density, chunky pixel treatment, outline thickness, cozy farming-RPG mood, relative scale, and simplified clean sprite rendering as the rest of the building set.
>
> **Composition.** Center the building in the canvas. Show the full building with minimal transparent padding. Transparent background. Clear silhouette. Keep the building isolated as a clean game asset sprite.
>
> **Design details.** [INSERT BUILDING DETAILS HERE]
>
> **Match the same camera angle, roof visibility, outline weight, and chunkier pixel-art rendering as the existing building set.**

**Master prompt — short form (single paragraph):**

> Create a pixel art PNG of a [BUILDING TYPE] for a cozy 2D farming RPG. Use a fixed elevated front-facing building view: show the full front facade, but also show most or nearly all of the roof from above, as if viewed at a high oblique angle. The roof should feel almost top-down while the front wall is still fully visible. No isometric view, no diagonal rotation, no realistic perspective, and no pure top-down roof-only view. Use chunky, visibly pixelated high-resolution pixel art with crisp hard edges, strong pixel blocks, dark outlines, simple clean sprite shading, no anti-aliasing, no smoothing, transparent background, minimal padding, and a warm cozy farming-RPG aesthetic. Keep the camera angle, roof visibility, pixel density, and overall sprite style consistent with the rest of the building set. Design details: [INSERT DETAILS]. Match the same camera angle, roof visibility, outline weight, and chunkier pixel-art rendering as the existing building set.

**Sizing reference (native PNG dimensions):**
| Asset type | Footprint (tiles) | Native PNG dimensions |
|---|---|---|
| Small house / cottage | 3w × 3h | 768 × 768 |
| Medium building (tavern, inn) | 4w × 4-5h | 768 × 768 to 1024 × 1024 |
| Large building (manor) | 5w × 5h | 1024 × 1024 |
| Tall tower / lighthouse | 2-3w × 5-7h | 384-512 × 1024+ |
| Wide creature (dragon) | 4w × 3h | 1024 × 768 |
| Hero sign / billboard | 4w × 2h | 1024 × 512 |

Keep the subject's real proportions — the sprite is no longer stretched to fill its footprint, so a square image of a 4-wide building comes out 4 tiles tall. **Native resolution is high (700-1200px) on purpose** — `tools/bridge-art/native_sprites.py` downsamples to 32 px per tile. Don't ask an image model for "low res pixel art at 64px"; it doesn't render small images well. Generate big, convert with the tool.

**Animation hooks.** When generating PNGs, design them so we can layer animation on top:
- **Chimney**: leave clear sky directly above the chimney top — no overhang or roof piece extending up there. Smoke needs vertical room.
- **Windows**: paint a flat warm yellow rectangle in the frame. Don't paint candles, faces, or detail inside the window. We pulse the window with a procedural overlay.
- **Door**: paint a closed door, rectangular and simple. We may overlay an "open" frame later.
- **Lantern by door**: paint the lantern body but the flame area should be a small empty circle/oval so we can flicker it procedurally.
- **Hanging sign**: chain from the building, with the sign hanging straight down (we may add a sway animation later).

## Character sprite sheets

Every walking character (the pilot now, NPCs next) uses this format:

| Spec | Value |
|---|---|
| Frame size | 32 × 48 native px (1 tile wide, 1.5 tall), feet 3 px above the bottom |
| Rows (direction order) | down, right, up, left |
| Columns | idle 0-3, then walk 0-7 — 12 × 4 = 384 × 192 px per sheet |
| Idle | ~340 ms per frame, sequence 0-1-2-1 |
| Walk | frame chosen from distance walked (8 frames per 2.4 tiles), not time |

The pilot uses this path (see "Characters — the Blender pipeline" below); the procedural drawer in `js/character.js` is only a fallback. NPCs are still procedural 16-unit tiles and should move to the same pipeline next.

| Spec | Value |
|---|---|
| Frame size | 80 × 92 native px (room for lunges, spins and the roll), the floor point at (40, 60) |
| Rows | down, right, up, left |
| Columns (39) | each weapon class's key poses, then the roll: `blade-` ready jab cross cut coil lunge · `sword-` wind sweep left right spin1 spin2 spin3 · `chop-` raise fall through raise2 through2 · `pole-` draw thrust reach back long · `maul-` heft over slam quake rise · `cast-` raise burst after · `pick-` up swing strike · `roll-` dive tuck1 tuck2 tuck3 rise — 3120 × 368 px |
| Timing | not in the sheet: js/arms.js strings the poses into swings with milliseconds per pose (`CLASSES`) |

**Weapons in hand** (`assets/characters/weapons/<id>.png` + `<id>.json`, `tools/bridge-art/weapon_sprites.py`): each weapon rendered in the pilot's hand for every pose of its class and every idle/walk frame (carrying it), for builds A and B, with the body held out (so whatever the hand, arm or body hides is already cut away), cropped and packed into one atlas. The JSON gives, per build → direction → frame name (`sword-sweep`, `walk3`, `idle0`…), `[x, y, w, h, dx, dy]` (dx, dy: the cropped frame's corner from the pilot's floor point), and `anchors`: the hand and the weapon's tip in each frame (px from the floor point) and whether the hand is in front of the body — the swing trails are drawn through the tip's path. `character.js drawFighter` puts the pilot frame and the weapon frame together and draws them as one sprite (depth-tested with `flat`: what's below the foot line lies on the floor in front, so a maul slammed down or a pike thrust toward you isn't hidden as if underground).

## Engine integration

### Adding a new PNG building / prop
1. Drop the painted PNG in `apps/bridge/assets/buildings/{name}.png` (or `props/`, `creatures/`).
2. Add it to `MANIFEST` in `tools/bridge-art/native_sprites.py` with its footprint width in tiles (and `True` for the matte flood if it has a dark background instead of white).
3. Run `python3 tools/bridge-art/native_sprites.py {name}` — it writes `assets/native/{name}.png` at exactly 32 px per tile (aspect kept, halo stripped, palette-aware downscale) and updates `assets/native/manifest.js`.
4. Draw it from a tile drawer with `BridgeSprites.draw(ctx, x, y, ts, '{name}', tilesW, tilesH, anchorOffsetX)` (or the world's `drawBuildingSprite`). It sits on the anchor tile's bottom edge, centred on the footprint, over a soft contact shadow.
5. Position overlays (smoke, window glow, spray) as fractions of `BridgeSprites.area(...)` — the rect the art actually occupies — never of the raw footprint.
6. In the world JSON, put the drawer's tile id on the anchor (bottom-centre) tile, set the footprint tiles to `0` (void) with `collisions = 1`.

### Characters — the Blender pipeline
Every character (the pilot, NPCs) is a cel-shaded 3D model rendered straight to 32 × 48 native frames by `tools/bridge-art/characters.py`, using the same 45° camera and tile units as the pre-rendered scenes (so a seated NPC sits at exactly stool height):

```
python3 -m venv BVENV && BVENV/bin/pip install bpy==5.2.2   # Python 3.13
BVENV/bin/python tools/bridge-art/characters.py /tmp/chars/pilot pilot
python3 tools/bridge-art/sprites_post.py pilot /tmp/chars/pilot
BVENV/bin/python tools/bridge-art/characters.py /tmp/chars/npc-bartender npc-bartender
python3 tools/bridge-art/sprites_post.py npc /tmp/chars/npc-bartender
```

- Shading happens in the shader: N·L against a fixed key light (high, upper-left), three flat tone bands per material, no lamps, one sample, no filtering, no dithering — every pixel is a palette colour.
- `sprites_post.py` draws line work where one body part overlaps another (from id + depth passes) and the outer outline, then packs one sheet per colour variant into `assets/characters/`.
- Sheet layout: rows down/right/up/left; columns idle 0-3, walk 0-7. Frames are 32 × 48 and the floor point under the character (feet, or seat for sitting poses) is pixel (16, 45).
- New NPCs are a `NPCS` entry in `characters.py` (skin, shirt, hair, hat, beard, apron, vest, pose — and the elves' options, see *Sylvara* under World palettes). A sheet renders in seconds, so look at it big before it goes in (frames scaled ×8) and again in the world at game scale. Dress options added for the Neon Royale, shared by anyone: `waistcoat` (closed, brass buttons, and a back — a white shirt's back reads as bare skin under warm light), `bib` (a shirt front down a jacket — a dinner suit is a dark `shirt` + `bib` + `bowtie`; a tuple colours it), `bowtie`, `coat` (a greatcoat's skirts, two rows of buttons, gold epaulettes), `sequin` (glints over a dress), `stole` (fur round the shoulders), `tray` (a server's tray of drinks at the shoulder), `shades`, `earpiece`, `gloves` (True white, or a tuple), `chrome_arm` (the left arm in steel), `pants` (a tone for the trousers: a white suit).
- **The pilot is customisable** (`js/look.js`, BridgeLook; localStorage `bridge_look`): build (A broad / B slight — `body_b()` reshapes any suit), hairstyle (`HAIRSTYLES`: short, long, ponytail, bun, curls, mohawk, shaved), a beard, the helmet on or off, skin tone and hair colour. Sheets are rendered per pose × suit × build × head (a head is `helmet`, `<hair>` or `<hair>-beard`) into `assets/characters/pilots/pilot[-sit|-ski|-climb|-attack][-<style>]-<a|b>-<head>.png` by `tools/bridge-art/pilots.sh` (all 70 runs; the 56 walking/seated/sport ones took ~45 min on two cores, the 14 attack runs and two weapon runs ~90 min, two at a time). Suit, skin and hair are rendered in **key colours** (`KEYS` in characters.py and look.js — keep the two in step) and look.js swaps them, and their line-work copies, as a sheet loads; so suit colours, skin tones and hair colours are free to add (a list entry in look.js, no re-render). A sheet key in character.js reads `[sit-|ski-|climb-|attack-][<style>-]<colour>@<look code>`. New pilots pick their look on the NEW PILOT screen; the wardrobe's *Change look* changes it later. With nothing saved, the helmet stays on.
- New pilot suits are a `build_<style>()` in `characters.py` (sharing `legs`, `arms` and `helmet` — which also builds the bare head and every hairstyle), added to the style map in the pilot branch and to `pilots.sh`; then an entry in `SUITS` in `js/gear.js`.
- **Fighting poses** (`pilot-attack[-<style>]-<a|b>-<head>`): `tools/bridge-art/attacks.py` holds the poses as plain numbers (per pose: the waist's lean and twist, each arm, each leg, where the weapon points — `aim` in the pilot's own frame — and how far along the haft the other hand reaches, `off`; a lunge, a spin, the roll's tumble), and `attack_rig.py` rigs the built suit for them (a waist pivot so the shoulders turn over planted feet, a grip in each hand) and turns the wrist to aim the weapon. `characters.py … pilot-weapons-<a|b>` builds every weapon in `weapon_sprites.py WEAPONS` in the grip and renders each one through its class's poses and the walk frames (the body as a holdout; the id pass marks the body white so the packer knows where it covers the weapon). `pilots.sh` does it all: `MODES="attack" WEAPONS=1 tools/bridge-art/pilots.sh BVENV/bin/python 2` (14 attack runs, one per suit × build doing all 15 heads, ~10 min each under load at two at a time, plus two weapon runs of ~4 min; packing runs on `PACK`, default `python3`, which needs numpy and Pillow — the Blender venv has neither). `MODES` picks the poses (`stand sit ski climb attack`), `WEAPONS=only` renders just the weapons (after adding one). Quick looks: `ATTACK_WEAPON=cutlass BVENV/bin/python tools/bridge-art/characters.py OUT pilot-attack-a short` renders the sheet with a weapon in hand as part of the pilot. Changing a pose means re-rendering every attack sheet (and the weapons); `python3 tools/bridge-art/attacks.py` rewrites attacks.json when columns change.

### Pre-rendered Blender scenes (the target for every world)
Rooms and areas are being rebuilt as Blender scenes. A scene is a script in `tools/bridge-art/scenes/` that places parts from an asset kit on the world's own tile grid, renders it, and rewrites the world JSON to match what was built (`scenekit.apply_world`: collisions from the placed objects, interactions moved onto their objects, NPC actors, the `scene` reference). Kits: `assets_lumar.py` (Lumar rooms — floors, walls, furniture, shop fittings, fireplaces, lamps), `assets_magic.py` (octagonal masonry rooms, angled windows, spell circles, candelabras, telescope…), `assets_cave.py` (rock faces, cave floor, lava, the dragon, hoard).

Done so far — every world: the tavern, inn, bakery, smithy, apothecary, the sorceress's tower, the dragon's cave, the pilot's quarters and the bridge (`assets_ship.py`), the six Arcadia interiors (`assets_cyber.py` — neon stroke-font signs, arcade cabinets with per-game screen art, shop/bar/clinic/pawn/repair fittings), Enigma Station and the Singularity (`assets_station.py`), and the outdoor worlds (`assets_town.py` — houses with shingled gable roofs and window boxes, cobbles, the fountain, bell tower, market stalls, trees, benches, bunting, lantern posts, running-bond flagstones, the broadside galleon and rowboats; `assets_cyber.py` storefronts, street lamps, puddles and planters for the Arcadia District): Lumar Harbour, the Market Square, the four islands, the Arcadia District. The Neon Royale (the casino) has its own kit, `assets_casino.py` (see *The Neon Royale* below).

```
BVENV/bin/python tools/bridge-art/scenes/lumar_tavern.py /tmp/tavern
python3 tools/bridge-art/scene_post.py /tmp/tavern apps/bridge/assets/scenes/lumar-tavern
```

- **Camera:** orthographic, 45° elevation; the world is stretched along rows by 1/sin 45° so every floor tile lands on an exact 32 × 32 px cell — the render lines up with the game grid.
- **Light is real:** Cycles renders lamps, fire and moonlight with cast shadows. `scene_post.py` shades it Cast n Chill-style: a smooth tone curve quantized into many small steps with 4 × 4 ordered dithering, colour of the light kept, soft lines (a deeper shade of the surface) where one part sits in front of another.
- **Firelight flickers:** each scene renders two light states (`full`, `dim`); the engine cross-fades them.
- **Depth, not layers:** `depth.png` stores per-pixel depth; `js/scene.js` depth-tests every character against it (a character is an upright billboard at its foot row), so walking behind tables, counters and stools is always right — no hand-sorted layers. People walking about (you and the other pilots: `drawOccluded(…, 'auto')`) show through as a faded copy of themselves once more than half of them is hidden — behind a lodge's long roof or a tall cabinet you'd otherwise vanish; behind a counter your legs just go (Beck saw people "being clipped"). Posed sports (ski, climb) use `xray: true`, a pale silhouette.
- **Characters pick up the room's light** from a per-tile light grid the render bakes (`tileLight` in `scene.json`).
- NPCs are `actors` in the world JSON's `scene` block (sheet, tile, facing, `pose: "sit"`), drawn with idle animation.
- **Scenekit primitives** (all in tile units — x, row, z): `box`, `cyl`, `cyl_x`, `cyl_y`, `sphere`, `cone`, plus oriented ones — `bar` (a box between two floor points, for angled walls and rune strokes), `tube` (cylinder/cone between two 3D points: limbs, telescopes, horns), `blob` (rotated ellipsoid), `rock` (faceted boulder) `poly` (flat surface: wing membranes, sails), `loft` (skin through cross-section rings: hulls, curved shells) and `boxes` (many boxes as one part — a tower's thousand lit windows). `assets_town` adds `annulus` (ring walls: basins, rims), `pyramid` (square roofs lined up with the walls — a 4-sided cone sits at 45°) and `lantern` (open iron frame round lit glass — never enclose an emissive part in a solid box). Meshes are built with bmesh, so a scene of a thousand-plus parts builds in seconds.
- **Glows add on top of the lit colour.** The glow you see is the emission colour × its strength (capped at 1); a strength above 1 only casts more light on the room. Give a glowing part a dark albedo and a saturated colour; bright albedo + strong emission clips to white. For a faint glow (puddles, coins under water) use a low strength.
- Mark tiles an object stands on with `k.solid(...)`, including tiles NPC actors stand on — `apply_world` only knows what you mark. Also block walkable tiles where a tall object in front would hide the player almost completely (behind cabinets, vending machines, the strip behind a row of houses). Along a side no longer than a tile, `k.solid` blocks only the cells the footprint covers at least 0.3 of (always at least the one under its centre): a barrel or a tree trunk blocks one tile, not two or four. Thin posts (lamps, flagpoles) use `k.solid_post(x, r)`: they block only the tiles where your feet would be on the pole (you stand at the bottom of your tile), so a post on a tile line is walked past on either side. Don't pad small props with a bigger `k.solid` of your own — what looks walkable should be — and keep a street's free row clear of posts, stalls and people.
- **Don't overlap coplanar boxes** (e.g. per-tile ground slabs that overhang each other): they catch each other's shadows and the tile grid shows as dark seams. Build one box per run of cells, or butt them exactly.
- **Coasts and water (Lumar):** land meets the sea in the render, not at a tile edge. `assets_coast.coast(k, walkable_cells, palette=…)` grows a heightfield round the walkable ground with a wandering edge (headlands and coves a tile in or out): a grass or sand lip, rock banks or beaches down to the waterline at `WZ` (z = −0.34; the ground is z = 0), a shallow shelf with kelp and glowing spore clumps, the seabed falling to the deep, rocks standing in the surf. It returns a `Terrain` (`.z(x, r)`) to set things on the banks. Ships ride in it: build them with `waterline=False` and lower them with `assets_coast.sink(k, since, WZ)` so the keel shows through the shallows. Setting `k.water_z` renders a height pass; `scene_post` writes `shore.png` (R: px from the waterline, G: depth under the surface, B: empty) and `scene.json` gets `water`.
- **The sea in the engine** (`js/sea.js`): `BridgeSea.drawSea` is the open sea behind a scene — two seamless dithered wave textures drifting, moon glints, spores — and `BridgeSea.drawWater` (the Lumar `ground` hook, right after the render) lays the same moving water over everything below the surface: thin over the shallows so sand, rocks and kelp show through, opaque in the deep where it meets the open sea without a seam, light rippling on the shallow bed, foam lapping in round rocks, beaches, piles and hulls. Composite the waves into the water mask with a pattern fill — `source-in` applies to the whole canvas on every draw, so tiled drawImage calls wipe each other.
- **Holes onto live art:** a part with albedo `'HOLDOUT'` renders transparent (viewports onto space). The world's `scene.sky` rect (screen tiles) tells the world script where to draw its animated sky; register it as the `behind` hook (below).
- **Swappable decor:** parts built inside `with k.variant(slot, key):` are left out of the base render and rendered alone in the room's light; `scene_post.py` writes them to `layers/<slot>/<key>/`. The world script calls `BridgeScene.setLayers(sceneId, {slot: key|null})` and the engine composites the chosen variants into the scene image and depth (the quarters' catalog decor and trophies work this way).
- **Live things in a scene world** register `BridgeWorld.registerSceneHooks(tileset, {behind, ground, items, over, post})`: `behind` draws before the render (shows through holes), `ground` right after it, under everyone (the Lumar water, the dock's containment field), `items` returns `{footRow, draw}` entries sorted with the characters — draw them with `BridgeScene.drawOccluded(...)` so furniture hides them correctly (the drone, the hologram, the Singularity's echoes) — `over` draws on top (steam, rain), and `post(ctx, buf, w, h, offX, offY, ts, now)` reworks the finished frame (the Singularity's gravitational warp, `js/horizon.js`). Hooks are per tileset, so a hook that only some of its worlds use keys off a block in the world JSON (`dock`, `horizon`, `skyline`) and does nothing without it. Hooks registered for `'*'` (`behind`, `ground`, `items`, `over`) run in every scene world after the tileset's own — the furniture in homes uses them. Registering again for the same tileset (or `'*'`) adds to what's there — each part runs in the order registered (magic, homes and the expedition all hook in).
- **Cache-busting:** `scene_post.py` stamps `scene.json` with `rev` (a hash of the PNGs); the engine fetches `scene.json` fresh and loads its images with `?v=rev`, and cutscene sprites carry a per-entry `rev` in `cine.json`. A re-rendered scene can never pair new collisions (world JSON) with a cached old image — always re-run `scene_post.py`, never copy PNGs by hand.
- **`scene.backdrop: true`** draws the world's own registered background (space, the void, the Lumar sea, Arcadia's skyline) wherever the render is empty — stations floating in space, islands in the sea. Such a world's camera follows the player (even with `fixedCamera`) and may show the whole render, margins included; a world JSON `"view": [x0, y0, x1, y1]` (tiles) narrows that, e.g. to keep the harbour framed. Never leave a render cut square where land meets it: a wider screen shows the cut, and the sloop draws every island whole from the sea. Diggen's Point (`scenes/lumar_harbor.py`) builds the whole headland in its render — cliffs running on past the map as one heightfield whose foot wanders off the tile grid, the town's roofs and bell tower over the brow, a wandering coast all round into deep water at the render's edge — so a wide screen just shows the point curving away into the sea.
- **Signs with real typefaces** (`assets_signs.py`, fonts in `tools/bridge-art/fonts/`, all OFL): `neon` (tubes tracing the letters' outlines), `letters` (extruded channel letters, lit or painted), `lightbox` (glowing box, dark lettering), `blade` (a vertical sign on brackets, one glyph a row) and a few neon icons. Pick a face per shop so every sign has its own character, and keep cap heights ≥ 0.5 tiles or the letters mush at 32 px a tile. `assets_dock.floor_text` paints stencil lettering flat on a deck.
- **The District kit** (`assets_district.py`): `frontage` builds a storefront by floors (cladding, window rows, balconies, fire escapes, AC units, side signs, posters, graffiti) and bespoke one-offs give each shop its own face — the arcade's canopy and portholes, the noodle bar's timber front, Lucky 7's bulb sign, the capsule hotel's pod wall, the club's monolith and velvet rope.
- **Arcadia's skyline** (`tools/bridge-art/skyline.py` + `assets_city.py` → `assets/backdrops/arcadia/`, drawn by `js/skyline.js`): three Blender layers at the scenes' 45° — `far` mega-towers sinking into smog, `mid` towers with blank holo-ad screens (CineKit anchors `ad<N>_a/_b` mark their corners) and `low`, the city under the walkway's railing — scrolled at different speeds, with a moon in smog, lanes of flying traffic, searchlights, animated holo-ads and rain (`BridgeSkyline.rain`, the arcadia `over` hook, for worlds with a `"skyline"` block).
- Ship scenes use `flicker.mode: "pulse"` — a slow breathing cross-fade between the light states for LED strips, instead of firelight flicker.

### Storage, selling and packs (`js/storage.js`, BridgeStorage)
Beck wanted places to keep things, somewhere to sell more often, and bigger packs he could find.
- **Chests**: aboard the Wayfarer from the start, the **sea chest** on the bridge and the **storage locker** in your quarters (24 slots each; the locker's Decor locker button opens the old decor locker), kept in localStorage `bridge_storage`. More are furniture (`CHESTS`): the **crate** (9), the **old trunk** (18) and the **captain's strongbox** (36, on the trunk's sprite — `SHARED` in `tools/bridge-art/furniture_sprites.py` keeps it in `furniture.json`), bought from the Ship's Chandler or any home's furnishing shop (H) and put down in any place of yours — the bridge and quarters, your houses, the farmhouse, the holm's cottage. A furniture chest keeps its things on its own layout entry (`items`, saved with `bridge_homes`, so a partner visiting sees the same chest; js/home.js carries them when you move it and won't put away a chest with anything in it). Opening a chest (an interaction of type `chest`, registered with `BridgeInteractions.register`) shows its slots above your pack in the Backpack: click a stack to move it across (shift-click or right-click: one), Store your pack (not the hotbar), Add to stacks, Take all, or drag.
- **Selling**: specialists pay full price (people.json `sell` topics: Oro, Maud, Hob, Marlo…). **General traders** take anything with a value (items.js `value`) for less — the Ship's Chandler's quartermaster's hatch aboard (6/10), Joro's pawn counter (6/10), the fishmonger in Lumar's square, Pennyworth's in Brambleford and the guide's hut in Fellhaven (7/10), the Crownhaven market (3/4) — interactions given type `trader` as their worlds load (`TRADERS`; they keep what they sold and offer Buy and Sell your goods). Each opens the game's own sell sheet (`BridgeStorage.sell` → an interaction of type `sell`); the Backpack's quick sell works at any of them. Keys, maps and things with no value don't sell.
- **The Ship's Chandler** on the bridge (type `chandler`): deck fittings (js/catalog.js), chests, packs (the Courier's Satchel and the Expedition Pack — `BridgeGear.SHOPS.wayfarer`), and selling. The Backpack names the next pack up and every outfitter that sells it.

### Interactions
`js/interactions.js` picks the target by proximity: anything within 1.5 tiles (the eight tiles round you, or the one you stand on), the one you face first, then the nearest; something two tiles ahead counts when a solid tile (a counter) stands between. No exact tile to stand on. The prompt is a small glass pill floating over the target — key cap, verb, name — built from the interaction's `prompt` (`"PRESS E TO TALK"` → *Talk*) and `label`; tap or click it to act. A soft pool of light marks the target's foot. Games get a small gold ▶ badge and exits a teal chevron; the one you're next to gives way to the pill. Clicking an object's body (up to two tiles above its tile) also uses it. A module can bring its own interaction type without a case in interactions.js: `BridgeInteractions.register(type, fn(inter), verb)` (chests, traders and the Chandler do). An interaction with an `action` goes to js/actions.js first (sit, sleep, view); the bridge's `deck` stations pass on through it to BridgeDeck.

### The two ships
Both are fantasy sci-fi, not NASA: the **Wayfarer** is a sky-galleon (indigo hull, gold wales, three masts of banded light-sails, a glowing keel fin, portholes and a stern castle) and the **skiff** an ivory-and-gold courier (bubble canopy, crescent wings, aether-ring nacelles with violet cores) — `assets_ship.mothership` / `assets_ship.shuttle`.
The **mothership** (bridge, quarters, hangar) jumps between systems from the nav chart (`js/starmap.js`: a pixel chart drawn in a native buffer, live planets, routes, ←/→ to pick, hold Enter/J/Space to charge and jump; the jump itself is `BridgeCine.jump` — the drive spooling with aether rings tightening round the hull, the leap (the ship stretching away into a white-out), the aether tunnel seen from the bridge through the gallery's arched windows (a per-pixel log-polar shader at half resolution, hoops and spiral light, dithered, its colour drifting violet → cyan → gold), dropping out over the destination, then the shuttle peeling off the bay for the planet; cuts are flashes (`dip: false` shots), each shot can fire a sound (`warp`, `leap`, `dropout`), Space/Esc/a click skips) and parks in orbit. **After a jump you go straight down**: `BridgeShip.descend` lands the shuttle on the world's pad — no stop on the bridge. The first time at a world the cutscene pauses on it with its name (`.cine-title`). The star map's *Stay aboard after the jump* (`bridge_stay_aboard`) keeps you on the bridge instead (the old *In orbit* card), to look out of the windows; every window on board draws the place below through `js/orbit.js` (`BridgeOrbit.draw` — per-pixel planets with a dithered terminator: Lumar's cloudy ocean, Arcadia's city-lit night side, Enigma's ringed giant, the Singularity, Verdance's green quilt of fields under two little moons, Hoarfell's ice). The **shuttle** flies you down: `js/ship.js` runs the flow (arrival card after a jump → lift off the hangar pad, seen from above in the world → a short fade → touch down on the world's pad, from above; "Return to ship" anywhere off the ship reverses it — no cutscene in between, by Beck's call: the top-down lift-off and landing are the good angles). A world with a landing pad has `"shuttle": {"spawn": [x, y]}` in its JSON and the parked shuttle as a scene decor layer (`with k.variant('shuttle', 'parked')`, default-on via the world JSON's `scene.layers`); while it flies the layer is switched off and its image drawn lifted with thrust, shadow and dust. The cutscenes (`js/cinematic.js`: the jump and the galleon) draw Blender sprites rendered side-on by `tools/bridge-art/cine_sprites.py` (`cinekit.CineKit`: the scene kit with a free camera, pitch and a sun; anchors such as engine exhausts land in `assets/cine/cine.json`) into a ~480 px native buffer scaled by a whole number. Between Lumar's docks you now sail the sloop yourself (see *Sailing the sloop yourself*); the galleon's passage on the open sea of `js/voyage.js` on autopilot (`BridgeVoyage.start(from, {auto: to})`) is the fallback: a route planned round the islands over the chart (A* on a coarse grid, coasts cost more, pulled straight and rounded), the ship casting off beside the island's moored galleon, running across the seas (each seam named as it's crossed) and gliding in to lie off the destination's berth, the camera leading the bow and settling to frame the island; a tap or Esc goes straight ashore. (`BridgeCine.sail`, the old side-on shot, is only a fallback now.)

### Big islands (Lumar)
Each Lumar island is a whole place to walk (≈56 × 40 tiles), built with `tools/bridge-art/assets_isle.py`: `mask()` unions noisy lobes into the island's shape (a C round a cove for Rose, a crescent town for Sapphire), `ground()` lays one continuous surface over it banded by a material function (paths, moor, meadow, ash, flagstones via `assets_town.island_ground` for towns) and can be sculpted (`height`: pools dug below the waterline fill with the sea's own water), `ridge()` raises cliffs with strata where the land climbs out of reach, and `assets_coast.coast()` takes the shore into the sea (`sheer` rects keep deep water right up to a quay wall; give one a fifth number, `soft`, and its seaward sides shelve into the shallows over that many tiles along a wandering line — a berth on a natural shore rather than a box cut into the sea, as on Starling Holm — and a sixth, `'all'`, for a pier off a beach with no wall at all, as on Tern Holm). Pass the island's own `(material, albedo)` as `ground=` to both `coast()` and `ridge()` (with `foot=`, how far the cliff's foot wanders in): the land then ends at the coast's wandering outline and the cliffs rise off a wandering line, never along the tile grid. Shape bays by carving the mask (Rose's `cove()`), not by leaving gaps between lobes — gaps come out as straight-sided rectangles. Mark small props (headstones) solid on their own tile only, or rows of them wall the player out. Each island has its own purpose and story: **Crimson Reach** (pirate camp, the Teeth, a ruined watchtower, the Ashen Ridge and the dragon's cave, a wreck on the reef, a rope bridge to a sea stack), **Rose Cove** (crystal terraces, a glasshouse, a chiming windmill, hot springs, an old mine), **Sapphire Port** (quay, market square, houses, the warehouse, a lighthouse whose beam sweeps the water, the potter's kiln) and **Midnight Isle** (the processional way of empty plinths, roaming stone sentinels, the graveyard of the drowned, the moon pool, abbey ruins, rolling mist). Scene extras the Lumar hooks animate: `smoke` (chimneys, kilns), `steam` (springs), `beacon` (a lighthouse lamp) and `mist`. Scripts: `scenes/lumar_crimson.py`, `lumar_rose.py`, `lumar_sapphire.py`, `lumar_midnight.py` (each rewrites its world JSON, keeping the DOCK sailing menu and the old labels so quests still match). Rose Cove's **glasshouse** opens (`lumar-rose-glasshouse`, `scenes/lumar_rose_glasshouse.py`): iron-framed glass, the night pink through it, raised grit beds of roseite growing in clusters — seedlings by the door, half-grown in the middle (ripe for picking: forage spots that grow back), the big ones humming against the glass — the cistern, the potting bench with its seed-crystals, and Liesl Marrow who keeps it (`liesl`, `npc-liesl`).

### Quests and people
- **Quests** (`assets/quests.json`, `js/quests.js`): each quest is a set of clues tied to interactions by `{world, label}`. Using one finds the clue — the first starts the quest, the last pays its reward through `BridgeProgression.recordAchievement('quest_<id>', coins)` (once per pilot). A toast reports each find; the journal (the game menu's Journal tab: J, or the Menu pill — see *The game menu*) lists what you've pieced together. Progress lives in localStorage. Keep labels stable when re-rendering a world, or the clue stops matching. A quest with `needs: <quest id>` doesn't begin until that one's done (a sequel: its first clue can sit on someone the earlier quest already used). A clue with `say` has its moment shown in place of the thing's usual words as it's found (`BridgeQuests.onInteract` returns the clues found just now). A person's topic can wait on a quest — `when: 'quest/clue'` (or `'quest'`, done; or a list) — and go once it's moved on (`until`); topics a quest has just opened come first in the list, lit up (`BridgeQuests.has`). **The log** (top of the journal, localStorage `bridge_log`, the last 250): what you've done, newest first, with where and when — every `BridgeQuests.toast` lands in it (they all say "J Journal", so the journal has to have it; `QUIET` skips passing hints like *Course set*), plus `BridgeQuests.arrived` (the first time you set foot in each place, from js/world.js) and the first time you meet each person (`BridgePeople.meet`). A new event worth remembering: toast it, or `BridgeQuests.note(kicker, title, sub)` to log it quietly. (Added after a new player found the journal empty: before it, a first hour of talking and wandering logged nothing.)
- **People** (`assets/people.json`, `js/people.js`): the cast. A person matched to a dialog interaction by `{world, label}` turns it into a conversation — portrait (the head and shoulders of the sheet's first frame, widened up to 28 px to take in whatever sticks out of the head — an elf's ears, a hat's brim), name and role, a greeting (another once you've met), topics to ask (who they are, their place, rumours that point at quests). Who you've met and what you've asked is remembered. These records are also the seed for any AI conversation layer later (persona + facts they know).

### Talking freely (AI conversations)
- **Server:** `api/talk.mjs` (Vercel function, Claude Haiku 5.5 at low effort, JSON replies). It builds every prompt itself — the browser never sends one — from `assets/people.json`, `assets/quests.json`, `assets/businesses.json` and `api/_personas.json`, the fuller character sheets (voice, story, what they know, secrets gated by trust, wants, how they see the others, story beats tied to quests or crew). Sheets live under `api/` so their secrets are never served to the page. Anyone without a sheet is voiced from their authored lines. GET `/api/talk` says whether it's on (`ANTHROPIC_API_KEY` set); without it the game hides free talk and the authored topics work as before.
- **Client:** `js/talk.js` (BridgeTalk) keeps a bond per person — `feeling` −10…10 (Cold / Wary / Neutral / Friendly / Warm / Trusts you), `mood`, up to 12 `memories` (older ones folded into a `summary` by the model), `met`, `last` — in localStorage and, once `docs/supabase/2026-10-14-pilot-bonds.sql` is applied, the pilot account. Each request sends the bond, found clue ids (so characters can't spoil quests), news since you last spoke (quests finished, crew hired, businesses bought) and flags for story beats.
- **In conversation** (`showConversation`): a text box under the topics (T or / to focus), your last line above theirs, how they feel beside their role; someone you've met greets you from memory (the authored line if the server is slow). Replies can nudge the crew or trade topic. Feeling ≤ −3 and they won't join your crew; ≥ 5 and they pay a tenth more for what you sell.
- **Letters:** mode `letter` writes a short signed letter in the character's voice from the same bond and news; the rack on the bridge holds them (see *The captain's deck*).
- **Story beats** (`beats` in a sheet) key off `quest:<id>` (finished) or `clue:<quest>/<clue>` (found along the way). The people a character knows (`others`, keyed by id) reach the model by name, never by id.
- **Adding a sheet:** a new key in `api/_personas.json` matching the person's id in `people.json`; keep facts consistent with the quests, and gate anything that would spoil one behind `trust`.

Stations are `deck` interactions handled by `BridgeDeck` in `js/worlds/bridge.js` (`action`): the chart desk opens the map of everything (the game menu's Map tab on *All places*), the wireless and the scope say what's out the window (`BridgeOrbit.getLocation()`), the aether gauges know whether you have an engineer, the letter rack opens your letters. The helm and the chart table open the nav chart; the hologram stands where the world JSON's `holo` says.

A slot is a decor `slot_key` like the quarters' ones.
- **Crew aboard:** once hired, a crew member leaves where you found them and stands at their post (`crewPosts` in `bridge.json`: Bram at the chart desk, Okafor at the gauges, Ansel at the wireless, Corra by the ledger, Pip on the sea chest) — `BridgeCrew.decorate`. Talking to them aboard still counts for quests that send you to them (`home`).

Envelopes show in the rack (the `mail` layer) while you have letters.

### Gathering, crew, businesses, the open sea
- **Forage** (`assets/forage.json`, `js/forage.js`): spots per world id, added to the world's interactions as it loads (re-renders can't lose them). A ready spot glints; gathering bounces its items out as loot (`BridgeLoot`); it grows back after `regrow` minutes. Items (crystals of four colours, sea glass, silver nails) live in `js/items.js`.
- **Fishing** (`assets/fishing.json`, `js/fishing.js`): spots per world id (a water tile off a jetty or a rocky point, a `pool`), added as `fish` interactions as the world loads. Each Lumar island has a long **fishing jetty** of its own, away from the sailing dock (`I.fishing_jetty` in `assets_isle.py`: a plank run with rope rails and piles, a head with a lantern, a bench, a bucket and rods; `I.jetty_cells` makes it walkable) — Sapphire's fishing pier runs six tiles out, Rose's reaches into the cove from the west arm, Crimson's goes east off the end of the beach, Midnight's out into the mist — and a spot off the rocks (Sapphire's west shore, Rose's point, by the wreck on Crimson). **In the world:** you turn to the water, the rod swings back as you charge, the line arcs out and the bobber rides the swell where it lands (further for a strong cast), ticks on a nibble, goes under on a bite, is dragged about as you reel and the catch flies in over the rail (`worldItems`, an `items` hook on the lumar, verdance and hoarfell tilesets); the panel moves to the top of the screen when you cast toward the bottom, and the interaction prompt hides while a line's out. The Lucky Horseshoe (carried) makes them bite sooner. Hold to cast (let go near the top of the swing to cast far — far casts favour the rare fish), wait, strike when the bobber goes under, then reel: hold to lift the catch zone, let go to drop it, keep the fish in it until the line's full (tuned so a calm player lands the commons almost every time; moon eels and star pearls fight). Pools by island: silverfin, spore minnows and crabs at the harbour, bluefin and rays off Sapphire, shrimp in Rose Cove, ember snappers and the Heron's silver coins off Crimson, moon eels round Midnight, star pearls in the moon pool, perch and sun carp in the farm pond on Verdance (drawn as fresh water in the sun, lily pads and all); old boots everywhere; messages in bottles (lore, each read once). The catch goes in the pack (fish are food) and sells to Oro; the game menu's Fish tab shows every fish, the ones caught with how many and the biggest, and the bottles' messages. **From a boat** (`js/sloop.js`): round up into the wind till she all but stops (|v| < 0.6) and the prompt is *Cast a line* (`fishHere` → `BridgeFishing.open({ pool: 'sea_<pal>', boat: true })`, the sea you're on); the panel goes to the top, the passage lies still while it's open (no steering, no update; the sail status reads *lying still*), and `drawRod` draws your line off the rail nearest the camera with fishing.js's own `drawLine` (the rod, the line, the bobber, the rings, the catch swung aboard). The sea pools are deeper water: bigger fish, the **spore tuna** and the **lantern angler** that only a boat finds, each sea's rare fish more often, and each sea's **legend** (only ever from a boat). A one-time hint (`bridge_sea_fish`) tells you about it the first time you're making way well out at sea, and one hail in three from a fisherman's dory is about the legend in that sea (`LEGEND` in sloop.js). The catch goes in her **fish hold** (below), not your pack.
- **Rarity** (`js/fishart.js` `TIER`: common, uncommon, rare, legendary; `TIERS` their names and colours). `FIGHTS` in fishing.js tunes each tier — the catch zone, how fast the line comes in and pays out, where it starts, how long you've got to strike — against a simulated player with a human reaction time: commons always land, uncommons ~85%, a rare one about half the time, a legend is a 13–17 s fight an average player wins about a third of the time. The fish is picked when it bites (so the bite already knows: *Strike! Something big!*, a bigger shadow under the water in the panel, a gold marker on the reel for a legend). Far casts (let go near the top) and the Lucky Horseshoe tip the odds toward the rare ones. The rare ones: **coral dragonet** (Rose), **cinder grouper** (Crimson), **starfin** (Midnight) — rarely off those piers, more often at sea — **jade marlin** (Emerald) and **glass swordfish** (Sapphire) from a boat, plus the sapphire ray, moon eel, lantern angler, sun carp and star pearl. The legends, one per sea, ~2% of bites out there: **Old Mossback** (Emerald), **Crownfin** (Sapphire), **Dawnveil** (Rose), **Emberjaw** (Crimson), the **Nightglass Coelacanth** (Midnight). Values climb with rarity (rares 45–120, legends 420–650); Zephyr pays value for all of them, Maud on Tern Holm pays a quarter more for fish.
- **The panel** (fishing.js `draw`, a 210 × 76 native scene shown at a whole multiple, like the world): the water side on, in the colour of the sea you're fishing (`WATER` by pool: emerald, sapphire, rose, crimson, midnight, the moon pool's silver, the farm pond in daylight, under the ice), the pier's planks and posts (the boat's rail at sea, the ice's lip on Fellhaven), your rod, the bobber on the surface and the hook below it, fish shadows swimming by. What bites is chosen as the cast lands, so its shadow comes in for the hook in the last moments before the bite — bigger for a rarer fish. **Perfect cast**: let go with the swing in the gold (`PERFECT_CAST`, the top 12%) — the longest cast, rare fish likelier, a quicker bite. **The strike**: a ring closes in round the bobber for as long as you've got; strike in its first 45% for a **perfect hook** (a head start on the line). **The reel**: a pixel gauge at the right — the green bar you hold up (bright while the fish is in it), the fish (in its rarity's colour), the line coming back; out of the bar the line goes red and the fish thrashes at the surface. **A chest** now and then (10–20%, more on far casts, more with the horseshoe): it drifts in the gauge; hold the bar on it for 1.4 s to bring it up with the fish — coins, sea glass, silver nails, a Heron coin or a star pearl (`openChest`). Words pop over the water (`pop`: PERFECT CAST, PERFECT HOOK, A CHEST, TREASURE, TOO SOON, SNAP). Landed, the fish leaps out onto the boards; lost, the line snaps or it swims off.
- **The catch card** (`reveal` in fishing.js, `#fish-reveal` in css): every catch comes up on a card — the fish drawn big by `BridgeFishArt.canvas(id, 48, 24, 5)` (crabs, boots, coins, pearls and bottles use their item icon), its rarity in its colour, its name, its size and *your biggest yet*, where it went (pack / fish hold n / cap / let go), what it's worth, and NEW the first time. Rare ones get rays and sparks and a bell chime (`rarecatch`), a legend a bigger burst, a gold flash, a shimmering name and a fanfare (`fanfare` in audio.js). A catch your pack can't take says *Your pack is full - make room for it*; putting the card away puts the rod down and opens the Backpack's swap (`BridgeInventory.offer`: drop something, send it to the ship or throw it away, or let the fish go). It takes no notice of keys or taps for 1.4 s (up to 3 s for a legend) and every press in that time makes it wait a little longer, so someone still hammering the reel can't knock it away; once *Space · carry on* shows, a fresh press puts it away (it goes by itself 3–7 s after that), and the next cast needs a fresh press too.
- **Fish art** (`js/fishart.js`, BridgeFishArt): fish painted from a description (`SPECS`: depth, where it's deepest, tail fork / crescent / round / fan / coel, dorsal low / spines / sail / crown / aft, bill, lure, barbels, finlets, glass, a pattern — spots, stars, stripes, bars, bands, flames, scales, squiggles, moss — and colours; eels and rays are their own shapes), at any size: the card's portrait with its glowing bits haloed, and 16 × 16 icons for the new fish (`art(id)` in items.js). A new fish: a spec here, a tier, an item, a `FIGHT` row and a pool.
- **Selling**: a conversation topic with `sell: [{id, price}]` (Oro on Sapphire, Joro in Arcadia) opens a sell sheet listing what they buy beside what you carry, each with its icon; you pick a count per item (none to start with, so nothing goes by accident; ←/→ or −/+, "all"), or sell everything they want at once. Goods leave the pack only once `BridgeProgression.awardCoins` succeeds.
- **Gear** (`js/gear.js`, BridgeGear): **suits** are Blender models (`characters.py pilot-<style>`: `coat`, `plate`, `thermal`, `runner`, `mystic`, `ranger`; the Flight Suit is plain `pilot`), rendered for every build and head and recoloured live (see *The pilot is customisable* above), picked by `character.js` from the style and colour you wear and the look you've chosen. Each has a perk: the Voyager's Coat +25 energy, the Neon Runner +15% speed, the Thermal Suit +20 health and keeps out the cold (`BridgeGear.has('cold')`, for the mountains), the Plated Suit +50 health and a little slower, the Starweave Robe +40 energy and the Ranger's Cloak +15 health and a little quicker (both from the Peddler). The colour is free to change any time. **Backpacks** add slots behind the hotbar (Flight Pack 6, Courier's Satchel 12, Expedition Pack 20, Voidweave Rucksack 30; the best you own is the one you carry). **Outfitters**: the travelling tailor in the Market Square (coat, satchel), the import stall on Sapphire (thermal), Cyber Gear on the District street (runner, expedition pack), Joro's back room (plate) and Vex's stash (voidweave) — set up on their interactions as worlds load (`PLACES` in gear.js) or from a conversation topic with `outfit: <shop>`. The **wardrobe** is the coat rack on the bridge, or OUTFIT (O) in the inventory screen; its *Change look* opens the look editor (free). Owned gear lives in localStorage `bridge_gear`; purchases go through `wagerCoins`.
- **The Collection** (`js/codex.js`, BridgeCodex; localStorage `bridge_codex`): the game menu's Collection tab — nine sets (`SETS`: fish, the **sea legends** (1500 for all five), crystals and ore, the farm, magic things, treasures, tools and weapons, food and drink, treasure maps; 92 things), each a grid of icons, found ones in colour, the rest as silhouettes with a hint where to look (hover or tap). Anything that lands in your pack counts (it wraps `BridgeInventory.addItem` and looks over the pack every few seconds; what you had already and every fish you've ever landed count quietly); a new find gets a toast, a finished set pays once (150-250, `codex_<set>`). A new collectible item: add it to its set with a hint.
- **Inventory** (`js/inventory.js`): the hotbar's ten slots, then the pack's rows; the inventory screen is the game menu's Backpack tab (I; see *The game menu*). Max health and energy follow the suit.
- **Crew** (`js/crew.js`, `crew` blocks in `assets/people.json`): hire someone from their conversation (wage via `wagerCoins`); perks other systems ask about with `BridgeCrew.has(perk)` — `navigator` (voyage speed), `quartermaster` (sell prices), `runner` (forage yield), `trader` (a cut when you make port in Lumar), `engineer` (businesses hold twice the hours of takings). A crew block with `after: <quest id>` answers `notYet` until that quest is complete — Okafor won't leave Enigma until you've found the Wren.
- **Businesses** (`assets/businesses.json`, `js/business.js`): tied to an interaction by `{world, label}`; buy, collect takings (`rate` coins an hour, up to `cap` hours), upgrade, put a crew member in charge (×1.5). Listed in the journal and on the nav chart.
- **People walking** (`assets/walkers.json`): routes of tile points per world, walked there and back with pauses, drawn with `BridgeScene` occlusion. Each world walks its own people: sailors, a fishwife and a dockhand on Lumar's quays, skiers in Fellhaven, a courier and a street samurai in the District (`npc-sailor`, `npc-fishwife`, `npc-dockhand`, `npc-skier-a/b`, `npc-courier`, `npc-samurai`), a high roller up the Royale's red carpet, cocktail servers with trays and gamblers on the casino floor (`npc-server`, `npc-server-b`, `npc-highroller`), three elves in Elderglade; nobody strolls on Midnight Isle. **A walker you can talk to** has `talk`: the label its people.json entry is `at` (and optionally `say`). `js/scene.js` carries a dialog interaction with it (`walker: '<world>#<i>'`, moved to its tile every frame), and while you're within a tile and a half it stops, turns to face you and waits (its clock is held, so it walks on from where it stopped when you go); the map marks it where you see it, or at the start of its route for a place you're not in (`BridgeScene.walkerInteractions`). Keep a talking walker's route on walkable tiles (the audit checks it).
- **The open sea** (`js/voyage.js`): the galleon's chart-scale sea, now only the sloop's fallback (`decorate` turns every Lumar DOCK/GALLEON into a single *Go sailing* — `go_sailing` — with no menu). The sea is five spore seas, like the book's: every point belongs to the nearest island's sea (measured from a noise-nudged position so the borders wander), each drawn in its own palette, with a seam of churning foam where two meet; crossing one names the sea you're entering. Islands are drawn from their own scene renders (cut at the waterline with `shore.png`, shrunk ×0.2); the berth is found from the world's DOCK interaction. NPC ships (traders, patrol, pirate, ghost), shoals to fish, salvage adrift; docking loads the island at its spawn. The same sea is the passage when you pick an island from a DOCK menu (autopilot, above). While it covers the screen the world underneath stops drawing (`BridgeVoyage.covers()`, main.js), and which sea each 4 px cell belongs to is worked out once and kept.

### Sailing the sloop yourself (Lumar)
Every Lumar DOCK says **Go sailing** (`go_sailing` → `BridgeSloop.board(worldId)`, `BridgeVoyage.start` as the fallback) and puts you in **the sloop** (`js/sloop.js`, BridgeSloop) at the world's own scale — no chart, no autopilot, no destination picked first. **Your sloop is the boat at the pier** — there are no galleons at the docks any more (taken out of every island render, by Beck's call: the boat you see tied up is the one that leaves). Each island has her lying broadside across the end of its pier (`MOORINGS`, checked against each render, drawn into the world by a `lumar` `items` hook, `mooredItems`, in the scene's depth order with lines to the bollards); wherever you go, she's at that pier. **Boarding happens in the world** (`board`): you walk down the pier and step down into her, she dips and rocks as you sit, and only then does the sea view take over, already aboard (`start(id, null, {aboard: true})`) — the world keeps drawing her with you in her until the sea view has faded in over it (`handoff`, `coverAt`: it used to drop her as the passage began loading, half a second of an empty pier), and the sea view's camera starts exactly where the world's was and eases onto the boat (where the world's camera is held off the map's edge it isn't on her); people aboard take the island's moonlight (`lightTint`, from `BridgeScene.tintAt` at her mooring), so you look the same in the boat as on the pier; arriving is the same the other way: coming alongside, the sea camera settles on your seat at her berth (`_seatCam`), and as you climb out the island's camera snaps straight there (`BridgeWorld.snapCamera()`, once) instead of panning down the pier from the quay's spawn as the sea fades; arriving, the island loads with you sat in her at its pier and you climb out and walk up onto dry land (`disembark`). With more than one of your ships at an island you're asked which to take (see *Your fleet* below); a bigger ship lies in line with the sloop off one end of the pier's end and you walk across the sloop's deck to reach her. **The sea is the chart** (Beck's call: sail anywhere, everything in its fixed place; without the chart you just can't find things). The water is the chart (`BridgeVoyage._isles`) at a fixed scale — `K` = 600 tiles a chart unit across, 0.72 of that down, the chart's own aspect — laid out from the island you cast off from (`toChart`/`toWorld`). Islands come up over the horizon as you near them: loaded within `LOAD_R` (60) tiles of their land, their own render and shore (not through BridgeScene, whose few cached scenes are the worlds you walk in), placed at their true offsets (`place`), let go past `DROP_R` (110). Each is its own render at full size with its own water (`BridgeSea.drawWaterAt`). Steer the wrong way and you miss them; keep on the right way and you arrive, charted or not. `EXT` holds each island's land (from its shore.png, round its map's centre) for steering round it and keeping the open-sea scatter off its coast — re-measure it if a render's coastline changes. Island to island it's ~110-150 tiles to an Emerald neighbour, ~230 to another sea, ~450 corner to corner — with a scripted helmsman about 1.5-2× the old two-island passage to an Emerald neighbour and ~3.5× into another sea, a minute and a half to two minutes of sailing either way (Beck: you got to the Crimson too fast). `K` is the one number to change if it wants to be shorter or longer.
- **Casting off** (`phase 'cast'`, `CAST` ms): (if you didn't board in the world, you walk down the pier and step aboard here), slip the bow line then the stern, shove off and she drifts clear along `castOut`, then hoist the main hand over hand before the sheet is yours. Coming in (`MOOR`) glides her onto the far island's mooring, turns her to its heading, throws the lines and you step ashore.
- **The chart** (`js/chart.js`, BridgeChart; localStorage `bridge_charts`): C (or the Chart pill, anywhere on Lumar; at sea C or the Chart button) opens a parchment chart of the five seas — drawn in a 400 × 264 native buffer scaled by a whole number (a touch under 1× on a phone), each island inked in sepia from its own render cut at the waterline (`shapeOf`), names and notes as text over it: what's there (`NOTES`), your ships at anchor, the contracts you're carrying there (a red seal), the holm's flag, you (a breathing red ring — at sea, exactly where you are on the water: `BridgeSloop.chartPos`, your position at the chart's fixed scale) and your course as a dotted gold line. **You start with the Emerald Sea charted** (Diggen's Point, Crownhaven, Tern Holm, Starling Holm); the other seas are hatched and their islands smudges until you buy their charts (`PRICES` 220-520, cheaper in that sea's own port) from any harbourmaster's book (*Charts*) or Ilsa Venn (*Sea charts*) — or until you've been there. Only islands you know are on the compass and in the course list. **Set a course** on it: ashore, the pier's DOCK then says *Sail for …* and the next passage is laid for it from the start (`BridgeChart.dest()` read by `start`), with the gold mark leading you out of your harbour's channel; at sea it sets one at once (`BridgeSloop.setCourse`, any time; a new course replaces the old). The passage waits while the chart is open. Arriving clears the course.
- **Setting a course:** out of the harbour mouth the compass marks every island on your chart by its initial, at its true bearing from where you are (the one you left too, once you're well away); hold a heading within ~24° of one (`aim`, the top panel says STEERING FOR …) for a couple of seconds at speed and that's your course (`commit`). The gold mark (`route`, laid again from wherever you've got to when you stray more than 24 tiles off it, `offCourse`) leads out of the harbour you're in by its channel, round any island in the way (`detour`: each island an ellipse from `EXT`, passed on its nearer side), and once the island's come up, in by its own channel to her berth. Esc (⋯ on touch) lists *Set a course for …* (or *Skip ahead* and *Change course* with one set) and *Open the chart*. The panel's bar is how much of the course you've sailed (`courseSailed` against what's left, `togo`). A line said while another's only just up waits its turn (`msgQ`), so a warning is never lost.
- **The boat** is a Blender sheet (`tools/bridge-art/sloop_sprites.py` → `assets/scenes/sloop`, cut at the water line with its own `shore.png`): the sloop's hull at 32 headings, a fisherman's dory at 8, and the sea's props (rocks, a reef, red and green buoys, a crate, a barrel), lit by the islands' moonlight. The mast, rigging, boom, mainsail and jib, pennant, tiller and the pilot (the seated sheet, on the windward bench) are drawn live in the boat's own frame, so the rig heels to leeward, the boom swings and the sails luff. Other boats' crews are the `npc-regular` sheet; their sails take `CLOTH` palettes.
- **Sailing:** ←/→ the tiller. By default **the sail trims itself** and ↑/↓ **raise and lower the sail** (`b.reef`, 0–1: speed scales with it and the sail is drawn reefed down to a scrap — lowering it is how you slow and stop, to fish or to grab flotsam; a squall hurts less with it down). **T** switches to trimming by hand (remembered in `bridge_sail_hand`): ↑ hauls the sheet in, ↓ eases it out, and the panel shows the sheet against the right band. Speed comes from a polar (nothing within 40° of the wind — in irons — best on a beam reach) times the trim: too far out luffs, too far in stalls. Forgiving where it used to bite: sit head to wind with the sail up and no hand on the tiller and her bow falls away by itself (`ironsT`); *Come alongside* works at any speed (she drops her sail as she comes in) within 3.4 tiles of the berth; flotsam can be hauled at up to 3.6 kn. Explained in plain words: the compass draws the no-go wedge (red) round where the wind comes from; the panel says INTO THE WIND — TURN AWAY / SAIL DOWN — ↑ TO RAISE IT / SAIL FLAPPING / SAIL TOO TIGHT / SAILING WELL and WIND FROM THE SIDE etc.; **How to sail** (`howTo()`: steer, the wind, speed, islands, arriving, stuck?) opens by itself on your first passage (`bridge_sail_taught`), from the menu, or with H. **Uncharted water:** the compass marks only islands on your chart, but every island is out there where the chart has it — sail its way and you'll find it. One you have no chart for comes up as *Land ho!* (`landHo`, 34 tiles off), shows as UNCHARTED ISLAND (`unchartedNear`), offers *Come alongside* with no name, and stays off your chart after you tie up (js/chart.js keeps it in `found`, not `visited`, and says to buy that sea's chart) — so it's hard to find again unless you remember the way. Its sea still takes on its colour on the chart, lightly, as any sea you've been in does (a charted one is full colour): the sea your mark is in (`BridgeSloop.chartPos`, read by js/chart.js each second) is kept in `sailed` and coloured from then on. **The edge of the known seas** (`EDGE`, chart 0.03-0.97 across, 0.04-0.96 down): the swell runs high and confused and a current sets you back toward the islands. Coming about the boom swings over; gybing it slams across. Gusts darken the water before they reach you. Leeway pushes you downwind when slow. Rocks, the reef and the shore push you off with a scrape; shallows drag the keel. Each sea has its own pace (`BASE`).
- **Wind and weather** (`windAt`, from `wind.seed`, where you are and `Date.now()`, so captain and crew see the same; the crew also gets the wind at the boat in `helm`): the wind's own slow veering and backing; a front now and then (`FRONT`, every 95 s a new `slotDir`) swinging it up to ~100° over half a minute, fresher behind a big one, said ~14 s before it comes (*The wind's backing - it'll come round to the north*, `windNews`); lulls where it all but dies (`lullAt`); islands shadow it in their lee and bend it along the shores it blows onto (`islandWind`). Weather systems drift across the sea (`genWeather`, one at most to a `WCELL` square of the chart's frame, each born, drifting ~40 tiles and dying away on its own clock): **rain squalls** — dark rough water under a grey curtain of falling rain you can see from well off (`drawWeatherWater`, `drawWeatherAir`), the wind gusty and swinging inside, rain over everything — and **fog banks**, a pale bank on the water that swallows you (the screen greys in, thicker on the Midnight Sea). One ahead is said before you reach it. The Crimson's squalls (most of its systems, plus its knock-downs) and Midnight's mist are the strong versions. The forgiving sailing holds through all of it (her bow still falls off in irons). Test hooks: `_sky()`, `_systems(x, r, T)`, `_front(T)`.
- **The seas you sail on** are the chart's own regions: `seaDists`/`seaField` mirror js/chart.js `seaAt` (the nearest island's sea, the borders nudged by noise, in the chart's 400 × 264 buffer; keep the two in step), with a pull toward each island's own sea round it so its render's water always matches, and a wobble at your own scale. `drawSeas` samples it on a 16 px grid, draws the sea most of the screen is in, clips each other sea to its region with marching squares and runs churning foam along every seam — so the water turns colour exactly where your mark crosses into another sea on the chart, course or no course. The sea you're in (`seaHere`) sets the wind's pace, the weather, the fishing pool and the story said as you cross (`crossing`, once it's held a moment).
- **The five seas have their stories** (`LORE`, said as you enter each): the Emerald, Sapphire and Rose are the calm trade water (`CALM`) — other sloops ply them (`traffic`, crewed, each going round its own long loop well off any island, timed by the clock so everyone sees them in the same place, keeping clear of you), the fisherman's dory rides at anchor, the spore whale surfaces. **The Crimson Sea** is squalls: rain, lightning with thunder after it (`storm`, the `thunder` sfx), hard gusts every few seconds; the traders give it a wide berth, so it's empty. **The Midnight Sea** nobody sails who doesn't have to: mist, extra rocks that hole you (a few health, never a knock-out — it stops at 10), a wreck on its side, will-o'-wisps (`wisps`) drifting, a bell somewhere, no traffic and no whale. Midnight Isle has no one walking its paths either (`walkers.json`).
- **On the way:** what's out on the water is seeded by where it lies (`genCell`: `CELLW`-tile squares of the chart's own frame, filled as you come near from their own seed and the sea they're in, never within 8 tiles of any island) — so it's the same every trip and for everyone aboard: rocks alone or in clusters, now and then a reef with rocks either side, a fisherman at anchor who answers a hail with a rumour (`LINES`: the sixth sea, the bell off the Teeth, Tamsin's signal; calm seas only), crates and barrels adrift to haul aboard (coins or goods; hauled ones are remembered by `key`), other sloops, Midnight's wrecks and lights. Channel buoys only at harbour mouths (lamps blinking, bells), gulls round the harbours (one follows you out), flying fish when you're quick, the spore whale once a passage well out in kind water, a glowing wake.
- **Arriving:** E (or a tap) within reach of any island's quay — the one you set a course for or not — brings you alongside (`moor(I)`, `dockAt`) and the island loads at its spawn by the dock; near your own quay you can put back in. Esc offers to keep sailing, skip ahead or put back. Sounds: the `lumar-passage` place (sea, wind, creak) and `luff`, `gybe`, `bell`, `thunder`.
- Test hooks: `BridgeSloop._phase()`, `_boat()`, `_isles()`, `_route()`, `_things()`, `_commit(id)`, `_moored()`, `_loaded()` (the islands up), `_toWorld(cx, cy)`, `_sea(x, r)`, `_snap()` (the camera onto the boat).

### Your fleet: ships, hands, cargo and trouble at sea (Lumar)
- **Ships** (`js/fleet.js`, BridgeFleet; localStorage `bridge_fleet`): a ladder that each sail differently — the sloop (the starter boat, always at whatever pier you're at), the **cutter** (quick, 40 crates, 1 gun, 1 hand), the **brigantine** (square-rigged forward: slow through a turn, poor to windward, shrugs off storms; 120 crates, 3 guns, 3 hands), the **galleon** (three masts of square sail, 300 crates, 5 guns, 5 hands, sails like a cathedral) and the **raider** (Crimson's pirate schooner, the fastest hull; 4 guns). `SHIPS` holds each one's length, beam, speed, turn, acceleration, how close to the wind she points (`nogo`), hold, hull, gun slots, hands needed, and how much storms and rocks hurt her. Every bigger ship lies where you last tied her up (`at`). `effective(ship)` folds in her fittings and crew; js/sloop.js sails `active()`. Each has a **fish hold** too (`fish`: sloop 8, raider 12, cutter 16, brigantine 30, galleon 50; `ship.catch`, `stowFish` / `takeFish` / `catchCount`): what you catch from her goes in it (the sailing HUD shows *FISH HOLD n / cap* under the passage panel), a full hold means you measure it and let it go, and when you tie up (or put back, or skip ahead) a *Landing the catch* menu offers to sell it all on the quay (`BridgeTrade.sellCatch`, the port's price for fish, with a glut like any sale), carry it ashore into your pack (`carryCatch`), or leave it aboard for a better market; her card at the harbourmaster shows the fish hold and lands it too. A wreck loses it.
- **How they're drawn:** hull sheets per ship (`tools/bridge-art/ship_sprites.py <type>` → `assets/scenes/ship-<type>`, 32 headings in cells of `HULLS[type].cell` tiles, the same 45° camera and moonlight as the sloop's): quarterdecks, forecastles, gun ports with guns run out, hatches, a ship's boat, lit stern windows and lanterns. The rig is drawn live from `RIGS` in sloop.js — fore-and-aft masts with booms, square masts whose yards brace round with the sheet (`squareMast`), headsails off a bowsprit, a wheel on the quarterdeck for anything over 3.6 tiles (you stand at it) — at heights that match the sheets (`deck`, `qd`, `bow`, a mast's own `z`). Other boats can be washed with a colour (`b.tint`: pirates tarred black, the drowned pale green).
- **At the pier** (`fleetAt`): the sloop lies across the pier's end (MOORINGS); each bigger ship of yours lies in line with her off one end or the other (or rafted outside if the shore's too close), so every ship casts off straight out. Boarding walks you down the pier, across the sloop and aboard (`wayAboard`, lifted onto each deck); arriving reverses it. In the passage the rest of your ships lie at every island you pass (`I.fleet`), and you can't sail through them.
- **The harbourmasters** (`js/harbour.js`, BridgeHarbour): one at the head of each pier (`PORTS`, added as the world loads; people.json `bess`, `aldous`, `mira`, `garro`, `ferryman` — sheets `npc-hm-*`, `npc-ferryman` in `characters.py`), whose *The harbour book* topic (`harbour: true`) opens: your ships (take one out, rename, sell to a yard, move or pay off hands), **the yard** (each port builds its own: cutters on Diggen's Point, brigantines and galleons at Sapphire's Great Yard, the raider on Crimson's pirate slip), **fit out** (`GUNS` for her slots — swivel, long nine, carronade, bow chaser, the Ferryman's moonglass harpoon — and `FITS` fitted once each: copper sheathing, oak doubling, Rose's crystal-weave sails and roseite sheathing, Crimson's storm rigging, Midnight's moon lantern), **repairs**, **sign on hands**, **the hold**, **market** and **contracts**.
- **Hands** (`recruits`): three people a day per port looking for a berth, from that sea (names, roles and skill by the date): deckhands, gunners (a gun with a gunner reloads twice as fast), navigators (quicker), riggers (handier, safer in storms), fighters (boarding), pursers (better prices). They live aboard one ship (`berths` = hands she needs + 2); a ship short of hands won't leave the pier (you're offered the sloop instead).
- **Cargo** (`js/trade.js`, BridgeTrade): goods ride in a ship's hold by the crate, never your pack — salt fish, spore-lamp oil and pine timber from Diggen's Point, Sapphire glass, Rose spore silk and roseite, Crimson ember rum and black powder, and the Ferryman's rare moon salt. Each port makes some cheap and wants others dear (`MARKET`), prices drift by the day and sag where you've just sold a lot (`glut`). What you mine, catch and gather goes in the hold too (`HAUL`, several to a crate) and sells at market. **Contracts**: two a day per port, carry so many crates of a good to another port by a day for a fee well over market; handed over when you open that port's book.
- **The journal** has a *Your fleet* section: every ship, where she lies (or how long till she's home from a voyage), what she carries, your hands, the contracts you've taken, the holm's strongbox. Markets have **depth**: a big deal moves the price (`BridgeTrade.price(id, port, side, n)`, `depth`), so a hold of one good sells for less each, and `bestRun` finds the cargo size that pays best.
- **Trouble at sea** (`js/seafight.js`, BridgeSeaFight, given an `api` into the passage by sloop.js): out in open water (a roll every 150 s of it, `openT`/`troubleAt`; the fight sees the stretch ahead through `stretch()`) the sea may bring pirates (now and then on the Emerald, more on the Sapphire and Rose, often on the Crimson, and more the richer your hold) or, on the Midnight Sea, a drowned ship. Pirates hail you: **pay them off** (a share of the hold's worth, or a third of the hold if you can't), **fight** (guns fire by themselves when loaded and bearing — side guns abeam, a chaser ahead; theirs too, so sail to keep them on your beam), or **run** (out-sail them and they give up; let them close and they board — fighters decide it). Beaten, they strike: coins and their cargo. The drowned don't hail; a moon lantern keeps them off (and thins the mist), moonglass bites them twice as hard. Shots fly as cannonballs (or green ghostfire) with smoke, splashes and hits; the hull bar shows top right; a hit shakes the view. **The Crimson's squalls** are deadly to a small boat: you're warned, and if you're carrying full sail when it hits she's knocked flat (hull damage × her `storm`); ease the sheet and she rides it out; now and then lightning takes the masthead. **Midnight's rocks** hole her (× `rocks`). A hull battered to nothing founders: salvors tow her into the nearer port (`BridgeFleet.wreck`), her hold lost, to be mended at the harbourmaster's. Test hooks: `BridgeSeaFight._spawn(kind)`, `_foes()`.

It *poses* the pilot (`BridgeCharacter.setPose({kind, x, y, row, col, flip, lift})`: the floor point under them in tile units, a frame of a sport sheet, mirrored or not, lifted off the ground in native px — the shadow and the depth test stay at the foot row, so a lifted pose is an upright billboard at that row, as high as it's drawn). The script writes what the game needs into the world JSON's `ski` block: per run its start, gates (`[x, row, width]`) and line; `jumps` (`[x, lip row, width, length, height]`); `grade` and `zone` (a character a tile: the pull down the fall line 0-9; groomed `.`, powder `~`, moguls `m`, ice `i`); `obstacles` (`[x, row, radius, kind]` — trees, rocks, lift towers: skiing collides with these circles, not their tiles, and with every other solid tile as a wall).

Runs: the Nursery Slope, Pinewood, the Couloir (once you've finished Pinewood). Saved in `bridge_ski` (per run: runs, best, the ghost; Liv's beaten runs); a finish pays (first, then once a day).

### Fighting
Creatures are `hostile` interactions run by the stalk-and-strike machine in `interactions.js` (idle → winding, the telegraph → striking → recovering; a strike lands only if you're still on the tile it locked onto, so stepping aside on the wind-up dodges it). `js/combat.js` (BridgeCombat) gives them a `creature` kind — health, damage, pace, drops, coins — and draws them in code on the 16-unit grid, gliding between tiles and depth-tested in scene worlds: **rock mites** (mine floors 3+), **cave crabs** (8+), **shades** (14+). Weapons are items with `damage`; F (or B on touch, or the right mouse button) swings the selected one, a weapon with `arc` cuts the tiles either side of the one you face too: the Iron Dagger (25) and the **Cutlass** (40, arc; the smithy on the square) and the **Star Blade** (80, arc; Hob forges it from 2 star iron, a songstone and coin). A pickaxe on F digs the rock you face, or hits a creature. At 0 health you black out (`BridgeCombat.faint`) and come round somewhere safe with half your health — in the mine, on a crate in the hall with Hob watching; on Midnight, on the pier under Morwen's blanket. The Plated Suit's +50 health is for this.

Playing together, creatures are shared and the fighting is co-op — see *Fighting together* under Multiplayer.

**How a weapon swings** (`js/arms.js`, BridgeArms) — added when Beck asked for "better animations… each weapon its own unique animation and a good kind of feel to it". Every weapon belongs to a **class** (items.js `cls`; anything else with `damage` counts as a blade, or a sword if it sweeps), and each class has its own rendered swings off the pilot's attack sheet (see *Character sprite sheets*), its own timing, sound and weight. A swing is a list of key poses with milliseconds each (`CLASSES`), and the blow lands on its **landing frame**, not on the key press — whatever's on the tiles then is struck. Through the wind-up and the landing you're held where you stand; in the recovery a step cuts it short, and pressing again chains into the next swing (within 420 ms of the last, `CHAIN_GAP`; a press during a swing is remembered). A weapon's `rate` scales its class's timing (the Veilpiercer's 170 against a blade's 260 runs every swing at 0.65).
- **Quick blade** (Iron Dagger, Veilpiercer, Twin Fangs): a jab, a backhand cut, then a lunging stab — ×1.5 and a tile further. ~180–300 ms a swing. Light hit-stop (40 ms).
- **Sword** (Cutlass, Star Blade, Moonglass Sabre): a wide sweep from right to left, back again left to right, and the third of a chain a full spin that cuts all eight tiles round you (×1.25).
- **Axe** (Rime Hatchet, Emberbrand — a broad blade that chops): up over the shoulder and down in a diagonal chop with weight behind it; the second, from the other shoulder, bites ×1.3. The camera kicks harder.
- **Polearm** (Boarding Pike): drawn back two-handed and thrust; a second thrust; the third a long lunge a tile further (×1.3) that pushes the creature back.
- **Maul** (War Maul): swung back, heaved up overhead, slammed down: a ground shock (`BridgeFX.spawnShock`, a ring and cracks) hits the tiles either side and beyond for 40%, the screen shakes, 110 ms of hit-stop.
- **Greatsword** (Tidebreaker, class `great`): swung off the maul's poses (`poses: 'maul'`) — lifted overhead two-handed and brought down in a cleave across three tiles.
- **Staff and wand** (Wispcaller, Moonlit Wand): raised, then thrust out — the bolt leaves the tip on the thrust (`BridgeMagic.cast` plays the swing and launches on its landing frame).
- **Pick** (the pickaxes, the ice axe, the hoe): up over the head and down on the tile in front — on a rock it breaks rock (`BridgeMine` strikes it on the landing frame, by E or F), on tilled-to-be earth it tills (`js/farm.js`), on a creature it's a blunt blow.
- **Charged swing**: keep F (B, the right button) held after a swing and the class's wind-up pose holds, motes drawn in to the hand, the pilot shaking once it's full (650 ms, `CHARGE_MS`); let go full for the big one — 4 energy: the blade's lunge ×2.2 a tile further, the sword's double spin ×2 all round that knocks them back, the axe's chop ×2.3 across three tiles, the pike's long lunge ×2.2 two tiles further, the maul's quake ×1.8 over the 3×3 in front, the greatsword's cleave ×2, a staff's bolt ×2, bigger, going on through whatever it meets, a pick ×2 into the rock. Let go early and nothing happens. (The item's own use runs again, charged — `pendingCharge` — so a pick still finds its rock.)
- **Dodge roll**: Shift (the ROLL button on touch, over A): up to two tiles the way you're pushing the stick or keys (else the way you face), stopping at whatever's in the way, 380 ms, 5 energy; for the first 85% of it nothing touches you (`BridgeArms.dodging()`: a strike that resolves on you then misses — *DODGED*). Rendered (the `roll-` columns: a dive, three frames balled up head over heels, up again), with dust where you set off and land. `BridgeCharacter.roll` moves you there, easing out.
- **Feel**: a landed hit freezes the swing and the creature for a moment (the class's `stop`: 40 ms for a blade up to 110 for the maul, longer for a finisher or a charged blow; the creature's own clocks are held too, so it doesn't strike through it) and it shudders, then recoils a few pixels away from you; the camera leans toward the blow (`BridgeWorld.kick`); the swing leaves a crisp arc of light through the tip's path (`BridgeFX.spawnTrail`, from the weapon's anchors, in its colour — steel, ember orange, frost blue, moonglass, star gold…); the hit throws an impact in its element (`BridgeFX.spawnImpact`: a steel star and sparks, frost shards, embers rising, a pillar of holy light, green drain wisps drawn back to you, dust and grit for heavy blows). Each class has its own whoosh and its own blow (`js/audio.js` `swing_<class>`, `impact_<class>`, plus `roll`, `dodge`, `charge`, `charged`).
- **Knock back**: `heavy` a tile (as before), a pike finisher or a charged sword spin a tile, the charged maul a tile — `w.push`, settled by `BridgeCombat.onHit` (a tile at a time, stopping at whatever's in the way; never the boss).
- **Weapons in hand**: the selected hotbar weapon is carried while you stand and walk (blades forward and down, the pike and the staff upright, the maul over the shoulder) and is in your hands for every swing — rendered with the pilot (see *Character sprite sheets*). New weapons: a model in `weapon_sprites.py`, an item with `cls`, `WEAPONS=only pilots.sh`.
- **The smithy on the square** also sells the **Twin Fangs** (18 a cut, quick, `twin`: a knife in each hand, every cut lands twice; 200) and the **Tidebreaker** (62, sweeps, slow; 480).
- **Stats everywhere a weapon's shown** (`BridgeArms.card` / `stats` / `line`): damage, speed (from the class's swings and the weapon's `rate`: Very quick, Quick, Normal, Slow, Very slow), reach, the class and what it does, each trait as an icon and a line (*Frost — slows what it hits for 3 s*, *Holy — ×1.6 against the undead*, *Sweep — hits the tiles either side*, *Heavy — staggers a wind-up and knocks back a tile*, *Drain — heals you a quarter of the damage*, *Twin*, *Quick*, *Bolt*, *Breaks rock*) and how it compares with what you're holding. See *The game menu* for where.

**Midnight Isle is where the fighting is** (the mine aside). As the island loads, `BridgeCombat.decorate` swaps the old JSON sentinels for its `ROSTER` (all spawned in code, on walkable cells): **Stone Sentinels** on the processional way (slow and heavy; cracked past half health, their blow becomes a slam that hits the tiles round the one they lock onto), **Drowned Wights** in the graveyard (struck, they may blink 2–3 tiles away — `blink`), **Will-o'-wisps** by the moon pool and the north woods (casters: `range` 4 — they keep their distance, line up with you and throw a bolt down the line; step off it), **Barrow Hounds** by the abbey (fast, short wind-up), and once a day **The Bell Warden** in the abbey ruins (a boss: a health bar across the top, a slam over a 3×3, a toll that rings out on the square two tiles from it — stand close or stand clear — and at two thirds and a third it calls two wisps; `bridge_midnight.day`). It drops the **Wispcaller Staff** the first time. One wight carries the **Shell Key** for the violet TOMB (`midnight_tomb`), which holds the **Veilpiercer**. Nobody walks Midnight's paths.
- **Reading a fight:** every creature's wind-up marks the tiles it will hit on the ground (`dangerCells`, a `ground` hook on the lumar and cave tilesets): red for a blow or a slam, gold for the toll's ring, violet for a bolt's target, the corners closing in as it comes. A hit on you shakes the screen (`BridgeCombat.shake`); a hit on them flashes them white (the flash, frost and burning are drawn on `performance.now()`, the clock the hits keep — the world's draw clock is `Date.now()`). Creatures path round headstones and plinths (`pathStep`, a short BFS when the straight step is blocked).
- **Weapon traits** (items with `damage`, read by `weaponUse` and `BridgeCombat.onHit`): `arc` sweeps the tiles either side; `reach` 2 hits the second tile too; `heavy` staggers a wind-up and knocks the creature back a tile; `frost` slows it (moves and wind-ups ×1.7, 3 s); `burn` sets it burning (3 a tick); `holy` bites the undead (wisps, wights, shades, the warden) ×1.6; `drain` gives you back a quarter of what it takes; `rate` scales its class's swing timing (js/arms.js); `twin` strikes twice; `cls` is its class. The smithy adds the **Boarding Pike** (34, reach 2; 160) and the **War Maul** (58, heavy, slow; 240); **Morwen's ARCANE CASE** in her tower sells the **Rime Hatchet** (38, frost; 340), the **Emberbrand** (44, burns; 380) and the **Moonglass Sabre** (50, arc, holy; 460); found: the **Veilpiercer** (32, quick, drains) and the **Wispcaller Staff** (42, holy; a wisp thrown seven tiles, 3 energy — `BridgeMagic.cast` with `bolt: 'wisp'`). Wisps drop **Wisp Embers**.

### Homes and furniture
`js/home.js` (BridgeHome). Places of your own: **the White House** on Sapphire Port's square (`lumar-home`, `scenes/lumar_home.py`: hearth, two windows on the sea, bare boards; 1500 coins) and a **capsule apartment** over the District's Capsule Hotel (`arcadia-home`, `scenes/arcadia_home.py`: a strip window onto the live skyline and rain — the `'*'` behind hook draws them in `scene.sky` — the sleeping capsule, a kitchenette; 600 coins). **The farmhouse** on Verdance (`verdance-home`, `scenes/verdance_home.py`: Edda's kitchen in daylight — whitewash over green wainscot, the black range, a dresser of blue-and-white plates, two windows on the field, her kitchen table with the ledger) comes with the farm's deed (`HOMES[id].farm`: `owns` asks `BridgeHomestead.owned()`; the FARMHOUSE door goes in once it's yours, and Edda's rocking chair and bed are waiting the first time). Their doors are `home_door` interactions set on the street as worlds load (`HOMES[id].door`: the WHITE HOUSE door at 38,13 on Sapphire; the CAPSULE HOTEL on the street): the first time they offer the place for sale (`wagerCoins`, a menu option `home_buy`), then let you in. Each comes with two pieces to start. Aboard, **your quarters and the bridge** are yours already. The rooms are rendered empty; everything else is what you put in them.
- **Furniture**: 36 pieces, each built with the scene kits' own builders by `tools/bridge-art/furniture_sprites.py` into one floorless sheet (`assets/scenes/furniture`, a 3 × 4-tile cell each, footprint at the bottom of its cell) plus `assets/furniture.json` (id, name, price, footprint `w` × `d`, `walk` for rugs, the footprint's corner on the sheet). The engine cuts each sprite at its cell's opaque bounds and draws it depth-tested against the room (`drawOccluded` at its front row, tinted by the room's light but softened, since the sheet is lit already); rugs sort under everyone, and a seat you're sitting on draws before you. Non-rug pieces block their tiles.
- **Pieces that do something** (`USES`): beds sleep, seats sit (one seat a tile: benches and sofas take two), the wardrobe opens the wardrobe, the arcade cabinet plays Asteroids, the CRT Breakout, the chess table chess, the telescope looks at the stars, the desk opens the journal, the clock tells the real time, the cat may allow a stroke, the lucky cat leaves 5 coins once a day, the bookshelf has a book for you. New piece: an entry in `PIECES` (furniture_sprites.py), re-render the sheet, and optionally a `USES` entry.
- **Furnishing** (H, or the Furnish pill, in a place of yours): the tray docks at the bottom (world-themed: parchment, neon, holo) and the camera frames the room above it (`BridgeWorld.reserveBottom`, `setFocus`). YOURS lists what you own, spare first; SHOP is the whole catalogue (a second tap buys, and the piece comes straight to your hands). Arrows/WASD or the mouse move the cursor (on touch: tap a tile, or the stick), E/click puts the piece down or picks one up, X puts one away, Z/C choose, Tab switches tabs, Esc or H is done. A piece can't go off the floor, on a door or the tiles round it, a spawn, a person, or anything you use, and never where it would cut off part of the floor or something you use (checked by flood fill from where you stand); rugs can go under furniture, not on other rugs.
- Saved in localStorage `bridge_homes`: `owned`, `have` (pieces bought), `layout` (per home: `{id, x, y}`, the footprint's top-left tile), `seen`. A piece placed in one home isn't spare for another.

### Sit, sleep, look out of the window
`js/actions.js` (BridgeActions) turns interactions into things you do, from `assets/actions.json` (by world id: tag interactions by label — or one at x, y — or `add` new ones where the art has a seat or a window). **sit**: the pilot sits on the `seat` (tile units, the floor point under the seat; `facing`) with the seated sheet (`pilot-sit-<suit>.png`, `characters.py pilot-sit`), energy comes back, moving gets you up; a seat with a `view` opens it too. **sleep**: the screen goes dark and you wake rested (`deny` says why not instead). **view**: first person — the room leans in toward the window (`#bridge-canvas.fp-lean`), then the view swivels in from that side to fill the screen (`#view-panel`, its canvas shaped to the screen; the window's frame and mullions round it indoors, open air outside, the eyepiece at a telescope; the caption along the bottom), and turns back when you look away. It shows, live, `sea` (the spore sea in the island's palette, its moon road and spores; `roofs` for a window over a town, `beam` for a lighthouse sweeping), `skyline` (Arcadia's layers framed for a window), `giant` (Enigma's ringed giant), `orbit` (the planet the Wayfarer is over), `void`, `stars` (a telescope). The interaction's text becomes the caption; quest clues still count. New seats and windows: add an entry, no re-render needed.

### Royale Link (the casino games)
The Neon Royale's games are one app, **Royale Link** (`apps/runouts`, served at `/runouts`; its own `CLAUDE.md` has the inside): blackjack, roulette, craps, hold'em, the slots, the derby, crash, and the sixteen Runouts games (back a player to win, finish safe or come last). `js/casino.js` (BridgeCasino) is the Bridge's side of it.
- **Interactions** (type `casino`, registered with `BridgeInteractions.register('casino', …, 'Play')`): `{ "type": "casino", "game": "blackjack", "table": "bj-2", "label": "BLACKJACK", "prompt": "PRESS E TO PLAY" }` — games `blackjack` `roulette` `craps` `poker` `slots` `derby` `crash` `runouts` (Runouts adds `"mode": "<id>"`, one of holdem, plo, rng, wheel, dice, high-card, coin-flips, black-marble, slots, horse-race, rocket, space-invaders, bomb, plinko, battle-royale, stock-market) and `"stakes": "high"` for the high-roller room's tables; `{ "type": "casino", "game": "lobby" }` is a Royale Link terminal. Table ids are free text (`bj-1`, `poker-3`); the app numbers the table and picks its felt, dealer and regulars from it, so two ids are two different tables (a poker table comes with its regulars seated). Using one opens the cabinet in the **casino frame** (gold on velvet, *NEON ROYALE* over the table's name) on `/runouts/?game=<game>&table=<id>[&mode=<id>][&stakes=high]`, a terminal on `/runouts/?link=1` (the lobby; `/runouts/?game=runouts` is the Runouts section). Any cabinet or app opened on a `/runouts` URL gets the casino frame. The Arcade's old RUNOUTS cabinets, the game room's slot, the nav chart's app list and `js/games.js` all point at Royale Link now; playing any table or terminal finds it (BridgeGames `runouts`). Badges and map markers treat `casino` as a game.
- **Coins**: in the cabinet the chips are the pilot's coins. The app asks and BridgeCasino stakes and pays through BridgeProgression (`wagerCoins` / `awardCoins`, reason `casino:<game>`), one message at a time in the order sent, moving the cabinet bar's coins as it goes (`BridgeCabinetModal.coins`): `bridge-casino-hello` → `-wallet { ok, balance, pilot, high }`; `-stake { id, amount, game, hold }` → `-staked { id, ok, balance }`; `-pay { id, amount, game, key, hold }` → `-paid` (once per key); `-hold { hold, game }`. `hold` is what the table owes the pilot if they walk away right now — bets not yet in play come back, a hand in play stands where it is and plays out, a spin or race already under way counts as it will land, a poker stack is the stack. **Closing the cabinet pays the hold** (`frameClosed`, then a toast: up or down for the visit); the app's first Esc in a round only warns. A page that closes with something held leaves it in localStorage `casino_open` (an entry per tab with the pilot's name, refreshed every 10 s; never cloud-synced, so two devices can't both pay it) and the next load pays it back once the entry is 30 s quiet (*Your chips came back*). Nothing is ever paid twice: payouts are keyed, the hold is cleared as it's paid.
- **Figures and the high-roller room**: lifetime staked and won per game in `bridge_casino` (cloud-saved). Poker's net (cash-outs less buy-ins) is `BridgeCasino.pokerWon()`; at `BridgeCasino.HIGH_ROLLER` (1000) the Royale notices you (a toast, once: *The Royale has noticed you — the high-roller room is open*) and `BridgeCasino.unlocked()` turns true — the hello then says `high`, and the app's lobby offers the high-roller room (higher limits: blackjack 100–10,000, hold'em 25/50 with a 1,000–10,000 buy-in, and so on). A `stakes: "high"` table opens at those limits whatever your winnings — put those behind the casino's own door.
- **Playing together** (js/together.js, `royale-<game>`): *Play a game…* lists the tables where you are (nearest of each), or *Royale Link* (a terminal, the game room's slot, or anywhere you've both played there) with its games inside. Blackjack, roulette, craps, the derby, crash and Runouts are *At one table* (*At one counter*): the two of you at the same table against the house — one shoe, one wheel, one shooter (whoever asked runs the table; the other sends their moves and is sent the table), the other's chips on the felt beside yours. Slots is *Side by side*: two machines, the other's spins on the glass beside yours. Hold'em is *Heads up* or *With the regulars* (two NPCs as well): your chips against each other's. There's no stake step — every bet is your own coins through your own cabinet, as when playing alone — and the verdict compares how each of you came out (*You beat the house*, *Alyssa came out ahead*; hold'em counts in your record). If one of you leaves, the other plays on (taking the table over if it was the host who went; at hold'em two regulars sit in). Talk across the table without leaving it: the 💬 pill in the cabinet's bar (js/tablechat.js, under Multiplayer).

### Time: each planet's clock, seasons, day and night, opening hours
Beck: "each place should have its own clock and timing cycle… tied to real hours of the day", with seasons, weather with real stakes and shops that keep hours. The plan is `_claude_docs/spec-living-worlds.md`.
- **The clock** (`js/clock.js`, BridgeClock): one clock for everyone, pinned to US Eastern time (`America/New_York`, so two pilots see the same sky). Each planet's day is a whole number of real hours that divides 24, starting at ET midnight — Sylvara 24 h, Hoarfell 12, Lumar 8 (days start at midnight, 8am and 4pm ET), Verdance 6; Arcadia is always night (busiest 8pm–1am ET, `bustle()`); Enigma, the Singularity and the ship keep no sun. A planet's clock reads hours and minutes into its own day (`time(planet).text`, Lumar `0:00`–`8:00`). **Seasons** on the real calendar, turning on Mondays: Verdance a week each (js/seasons.js now counts days by this clock), Lumar two weeks each, Hoarfell three weeks of winter and one of each of the others, Sylvara the real moon (`moon()`: its full moon is the real full moon; the week round the new moon is *the Dimming*). **Daylight** (`daylight(planet)`, the share of the day the sun is up) moves smoothly through the year: Lumar and Verdance 65% at midsummer, 50% at the equinoxes, 35% at midwinter; Hoarfell's midnight sun (it never sets — "night" is a golden glow) and polar night (~12%); Sylvara a steady 55%, its dusk and dawn spreading over most of the day in the Dimming. `sky(worldId)` gives `sun` (0 night … 1 day: smoothstep of the sun's elevation `cos(2π(t/len − ½)) − cos(πD)`), `dusk` (the warm light at the horizon), the moon, the season, sunrise and sunset and a `part` (dawn, morning, midday, afternoon, dusk, night, midnight sun); dawn and dusk each last about a twelfth of the day. The Midnight Isle never sees the sun. **Previews:** `?at=2026-10-16T21:30` (an ET wall time) and `&timewarp=60`, or `BridgeClock._at(ms | 'ET string', warp)`.
- **Day and night in the art:** a scene rendered for more than one time of day has `cycle` in its scene.json (`{day, dusk, night}` → light state names) and js/scene.js draws it as a blend: night first (with its firelight flicker), dusk over it (weight `dusk × 0.9`), day over that (`sun × (1 − dusk weight)`), only the ones that show; characters' light (`tintAt`) blends the same way; `BridgeScene.sky(id)` / `shownState(id)` for anything drawn from one state (layer images, the map). The sea follows the scene it's round (js/sea.js `DAY` palettes and derived `@dusk` ones, sun sparkle by day, spores only in the dark) — never ahead of the island's art. **Rendering it** (`tools/bridge-art/scenekit.py` `render(…, cycle=…)` or `SCENE_CYCLE=night|day` on any scene script): a scene lit for night (Lumar's moonlight and lanterns) gets a `day` state (a sun, `_day`) and a `dusk` one (a low warm sun, `_dusk`), its own states staying the night ones; a scene lit by day (Verdance, Hoarfell) gets `dusk` and `night` (a moon over the whole place, `_moon`, and the lamps up). The kit tells the sky from the lamps by itself — suns and area lights eight tiles or more across are the sky (`_sky`), everything else a lamp (`_art`) — and a state's `_emit` scales how much glowing parts glow and cast (lamps out by day), `_world` its ambient sky. `scene_post.py` scales the emission per state and writes `cycle` into scene.json. The old `full` / `dim` names stay, so anything that loads `full.png` (the sloop, the chart, treasure maps) still gets the art it always had.
- **Opening hours** (`js/hours.js`, BridgeHours): `HOURS[world][label] = [from, to]` in anchors that move with the sky — `midnight`, `small` (just past it), `dawn`, `sunrise`, `morning`, `noon`, `afternoon`, `sunset`, `evening`, `late` — or fractions of the day (`to` before `from` runs past midnight). The working day is civil: shops keep at least the middle 40% of it, and keep their hours under the midnight sun. js/interactions.js `executeInteraction` asks `BridgeHours.gate(inter)` first: a shut counter says so — the hours on the door in that planet's time and how long till it opens — instead of opening. Lumar's bakery opens at dawn, its smithy and stalls in daylight, its taverns from noon till just past midnight; Verdance's shops likewise on its 6-hour day; Hoarfell's lodge never shuts.
- **The sky by the place's name**: a sun, a moon or half of each (dawn, dusk) beside the location badge, its season on hover (`.world-sky`); the time itself is for a timepiece. On Lumar's open ground the chapels ring the hours (`bell`, a toast that stays out of the journal).
- **The ship's chronometer**: the wireless on the bridge reads every planet's time, part of the day and season (`BridgeHours.chronometer()`).
- Test: `node tools/tests/run.js world` (`world/clock.js`).

### Sound
`js/audio.js` (BridgeAudio): everything is synthesised with Web Audio — no sound files. **Music** is generated as it plays from a theme (`THEMES`: tempo, root, mode, chord degrees per bar, and a band — pad, arpeggio, bass, an improvised lead built from chord tones in A A' B A phrases, percussion), through a shared reverb and echo; every eight bars the band thins or fills. `themeFor(worldId)` picks the theme and the **ambience** beds (`BEDS`: sea, wind, rain, city, hum, engine, creak, fire, murmur, crowd, bleeps, beeps, drips, rumble, breeze, birds, snowwind, gale, chimes, slots, chips): Lumar outdoors folk over the sea, Lumar indoors warm by the fire, Arcadia streets synthwave in the rain, arcades chiptune, back rooms lo-fi, the Neon Royale smoky lounge jazz (`casino`: a walking bass — `bass.walk` — brushes and the ride, keys comping, a synth sax) over the crowd and the slot floor's chimes and payouts (`slots`), the Card Room over chips clacking (`chips`), Enigma drones and sonar, the Singularity deep and glassy, Verdance a folk tune over birdsong, Hoarfell bells over the snow wind, the Wayfarer a music box over the engine, caves and towers their own. Themes and beds cross-fade on every world change (`setWorld`, called from world.js). **Effects**: `BridgeAudio.sfx(name)` (doors, dialogs, clues, quests, coins, pickups, footsteps, sitting, sleeping, fishing, Splice, pachinko; fighting: a whoosh and a blow per weapon class, `swing_<class>` / `impact_<class>`, made from `whoosh()` — noise through a band sliding from one pitch to another — plus `roll`, `dodge`, `charge`, `charged`). The ♪ pill (or M) cycles sound on → effects only → off, saved in `bridge_audio`. Audio starts on the first tap or key.

### Lighting
A world opts in with a `lighting` block in its JSON (see the header of `js/lighting.js` for every field): an `ambient` colour, `fromGlow` (reuse the world's `tileGlow` tiles as lights, with `skip` for things like glowing sea), `tileLights` (a light on every tile of a type — lanterns, fireplaces, lava), hand-placed `lights`, a faint `pilot` light and `bloom`. Keep lights where the art shows a source, warm for fire and lamps, coloured for magic and neon. Lighting is subtle on the ship and stations and moody at night in Lumar.

### Ground under objects
Lumar object tiles (NPCs, lanterns, crates, stalls) paint the world's ground under themselves via `drawGround()`. A world chooses it with `"groundTile"` in its JSON (e.g. `28` cobblestone in the Market Square). New object drawers should call `drawGround`, not a specific floor.

Pushes every 10 s when something changed and when the tab hides. The browser remembers whose game it holds (`bridge_owner`): signing in as someone else on the same browser saves the last pilot's changes to their row, clears the game (hotbar and world position too) and brings yours. A device's first sync with progress of its own keeps whichever game is bigger; anything replaced is kept locally in `bridge_cloud_backup`. `BridgeCloud.peek(id)` / `.write(id, key, value)` read and write another pilot's save (visiting a partner's places). ## Don't

- Don't ask the image model for "isometric," "diagonal rotation," "realistic perspective," "side view," or "pure top-down roof-only view." High-oblique elevated front-facing only.
- Don't generate PNGs at 64×64 native — image models render small badly. Generate 700-1200px and let chunkify handle resolution.
- Don't paint window interiors in PNGs. Yellow rectangle only — we overlay glow.
- Don't use sub-tile detail in procedural drawers. Whole `u` units only for foreground subjects.
- Don't load or stretch full-size PNGs at runtime — convert them to native sprites with the tool.
- Don't count frames for timing — use elapsed time.
- Don't draw text into the world buffer; text belongs in the screen-space layer.
- Don't introduce a new color palette without adding it to this doc first.
- Don't mix view angles in the same world — every building must use the same high-oblique camera.
- Don't generate art with these prompts for any other Becknology app (aether-seas, cipher-room, etc.). These rules apply to the **bridge app only**.

- **Tavern PNG** at `apps/bridge/assets/buildings/tavern.png` — gold standard for building art.
- **Procedural lantern** at `drawLantern` in `js/worlds/lumar.js` — gold standard for matching procedural style (limited palette, hard edges, 1-px outline).
- **Animated sea bands** at `drawSeaShared` — gold standard for procedural animation.
